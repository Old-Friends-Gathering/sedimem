## 1. 问题

现有记忆系统（claude-mem / mem0 / dsh-memory / CLAUDE.md 约定）把「记忆」当成**检索问题**，用更大上下文、更强 embedding 去提高召回；但用户实际感受到的痛是**治理问题**：冗余、重复、互相矛盾、越用越脏。BEAM（ICLR 2026, arXiv:2510.27246）也确认：所有记忆系统最弱的是矛盾消解，其次时序推理与知识更新。

**memo 的定位**：一个薄的治理层。检索够用即可（词法 + 实体键），把工程预算花在「写入门控 / 冲突失效 / 离线整合 / 检索期过滤」四条路径上。

## 2. 六条硬需求（验收口径）

| # | 需求 | 验收（可执行） |
|---|---|---|
| C1 | 本地离线：无 API key、无外部服务、断网可用 | 无网络环境写入 + 新进程召回成功 |
| C2 | 三端同一份记忆：DSH / Codex / Claude Code | A 写 → 新会话 B（另两端）召回并正确使用 |
| C3 | 重复不增长：同一事实换 5 种措辞写 5 次 | 存储 active 条数不变；检索无重复；token 不膨胀 |
| C4 | 冲突可失效：事实变更后旧值不命中，但仍可 as-of 回查 | 冲突注入 + `asOf` 查询通过 |
| C5 | 自治：无需人工整理，库自己变干净 | 夜间整合跑通、裁决队列可清空、指标不恶化 |
| C6 | 轻：≤1 进程、无 Docker、无图库、零运行时依赖 | 装机 <5 分钟；常驻内存 <100MB |

## 3. 设计原则（不可违背）

1. **真相层不可变**：记忆只追加，不原地改写。变更 = 追加新版本 + 旧版本写 `valid_to`。
2. **派生层可弃**：索引、brief、指标全部可由真相层重建；重建过程**不得**修改真相层（禁止在 load/build 路径做 mutation）。
3. **过时即失效，不是删除**：删除只写墓碑（`status=tombstoned`），物理清理延迟且有审计。
4. **机器只做确定性判断**：hash、实体键、时间比较、TTL、配额 —— 全部可单测、无随机性。
5. **LLM 只裁决不扫描**：只有超出阈值的**候选对**才进入裁决队列，且由用户当前在用的 Agent 签字，可审计、可回放。
6. **一切可替换**：Storage / Index / Judge / Renderer / Clock 都是 Port；v0.1 的实现是最笨但最可测的那一版。
7. **方向性函数必须单调**：衰减、置信度、排序权重必须有单调性单测（MemoryBank 的 `exp(-t/5*S)` 被解析成 `((-t)/5)*S`，导致「越常回忆越快被删」）。
8. **不确定就标 disputed**：裁决失败宁可并存 + 标记，不可静默覆盖（静默篡改历史比脏更危险）。

## 4. 非目标（v0.1 明确不做）

- 不做向量/图数据库、不做 embedding（P4 可选，走 IndexPort 适配器）。
- 不做跨机同步（P4，走 git）。
- 不做自动摘要分层（P2 之后的候选区机制）。
- 不做 UI。
- 不接管 `CLAUDE.md` / `AGENTS.md` 里的**指令**（那是上下文，不是记忆）。
