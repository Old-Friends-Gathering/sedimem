## 0. 结论与定位

Sedimem 是本地优先、可审计、可评测的 Agent 长期记忆与上下文引擎。展示重点是：如何从复杂对话中提取有证据的候选记忆，如何纠错和维护有效状态，如何在 token 预算内提供有用上下文，以及如何用实验证明收益。

- 保留 JSONL append-only 真相层、可重建派生层、治理门禁、MCP、任务账本和观测台。
- 主线改为 **评测 → 证据约束抽取 → 长期记忆接纳与纠错 → 混合检索 → 预算装配 → Agent 任务验证**。
- “不能有错”落实为可执行防线，不承诺开放环境零幻觉：无证据拒绝、未知留空、候选不冒充事实、关键变更人工接纳、严重错误阻断发布。
- 不以 star 数或“功能别人已经做了”否决学习价值；也不以堆框架、图数据库或连接器数量证明 AI-Native。
- 本期不做通用 Agent 框架、聊天产品、云同步、多人权限、自修改系统 Prompt、自动外部动作。

### 0.1 从开源项目采用什么

| 来源 | 采用机制 | 落到本计划 |
|---|---|---|
| Mem0 | 原子抽取、关联已有记忆、约束候选 ID | P1b 候选抽取；角色与断言必须另外核验 |
| LangMem | 语义/经历/程序记忆分工，前台与后台分离 | P1a 评测分类；P1b 异步候选；程序知识先人工确认 |
| Graphiti | 事件来源、有效与失效时间 | P1b 证据定位；P2 纠错失效；不引图数据库 |
| Letta Code | 热上下文与可搜索消息分层 | P1c 装配与按需展开；不重做 harness |
| claude-mem | 紧凑索引和渐进展开 | P1c 索引→片段→原文，不全量塞进 prompt |
| Hindsight | 证据事实与归纳分层，归纳保留支撑证据 | P1b 证据候选；P2 可失效归纳 |
| LongMemEval | 抽取、跨会话、更新、时间与拒答评测 | P1a 起建立效果基线 |

机制事实的引用及版本边界见调研报告。各项目的安全性、性能优劣不在本轮验证范围。

### 0.3 工作规则与红线

1. 文档先行：规格/ADR → 阶段计划 → 失败测试与 eval → 实现 → 文档同步。计划不代替运行契约。
2. TDD + eval；沿用现有 quality/security/coverage/docs-drift 门禁，覆盖率 lines ≥85 / branches ≥70 / functions ≥90。确定性单测与 LLM 效果评测分开报告。
3. 阈值、预算、超时、重试全部进版本配置并记录来源、回滚方法；不得散落魔法数字。本稿评测数字是项目风险取舍，不是论文结论，实施时进入 eval 配置。
4. push/PR 前按既有规定至少两个独立审核（架构、抽取准确性/安全），修完 blocker；本轮文档更新不等于已通过独立审核，不 push、不建 PR。子代理延续用户 GLM-5.3 约束；本环境未暴露该模型，不伪称执行。
5. 原始 items 只追加；更新/失效/删除留版本与审计；派生可删可重建。显式维护 compact 的例外及删除含义仍以现行契约为准。
6. trust/taint/sourceRefs 不能因模型摘要、复核、人工“接纳候选”而自动提升；T2 仍不进入可信 facts，trust 提升沿用显式人工操作和理由。
7. 凭据不入 env/仓库/日志；默认不出站。启用模型前明确目的地与发送字段并脱敏；本地存储不等于抽取数据不出机。
8. 语义检索、抽取、来源恢复失败显式 degraded/error；不得把失败当“没有记忆”。同 UID 不承诺机密。
9. 不破坏现有 MEMO_HOME 与记录版本兼容性；新增字段可缺省，变更先 ADR 与迁移/回滚设计。
10. 公共演示使用标明合成的脱敏数据；不得公布真实 transcript、SN、邮箱或本机路径。任务库保持 open，不因本轮研究执行 close/晋升。

## 1. 当前资产与缺口

已有：JSONL、索引、语义 port/RRF、LLM sidecar、checkpoint、segments/brief/expand、trust/taint、注入审计基础、UI。

缺口或需验证：证据到单个 claim 的绑定；跨段角色/否定/纠正；抽取 precision/recall；候选接纳状态机；以 token 为单位装配；端到端任务增益。不能把“已有模块”写成“效果达标”。

最新 handoff 为 P0b 完成、P1 未开始；账本 brief 仍混合 v1.0/v1.2 待办。这作为脱敏回归模式：历史进展可搜索，当前 pending 只能由有依据的最新状态投影产生；矛盾未消解则标 disputed，不能仅取最后一句猜结论。

## 2. 目标数据流与层次

```mermaid
flowchart LR
    A[授权的转录或事件] --> B[规范化与脱敏]
    B --> C[稳定事件及证据片段]
    C --> D[LLM 原子候选抽取]
    D --> E[结构校验及证据核对]
    E --> F[待复核候选]
    F --> G[人工接纳及显式写入]
    G --> H[长期真相层]
    H --> I[混合检索与状态过滤]
    C --> I
    I --> J[token 预算装配]
    J --> K[Agent 任务与评测回执]
```

四类数据分别保存：来源证据（本地授权保留）、候选（非事实）、已接纳长期记录（真相层）、摘要/向量/pack（可弃派生）。session 段继续不进主库 facts；允许 pack 显式检索 ledger，单独 references 分区，不隐式改变主库 search 范围。

复用现有 LlmPort、session 与四道门，不建另一套摄取管道；候选持久化位置、生命周期和 API 在 P1a 规格确定。直接手写 memory_write 保持兼容；新增抽取候选入口不冒充它。

## 3. 上下文抽取：最高优先级

### 3.1 输入与分段

- 保留 role、speaker、tool 状态、task/scope、eventId、事件时间、来源 hash；先脱敏再发模型/落派生盘。
- 按事件/话题及 token 窗口切段，保留必要重叠和回复关系。不能只截前后文而不声明中间缺口。
- 抽取游标只在候选和审计持久化后提交；崩溃重放幂等，缺口有 missingRanges，不能推进为“已完成”。
- 已有摘要只用于导航/辅助指代，不作为新事实的独立证据；来源缺失则拒绝晋升。

### 3.2 原子候选的必要语义（计划字段，非现行 schema）

| 类别 | 必须保留的信息 |
|---|---|
| 身份 | candidateId、schemaVersion、scope/task、输入范围 hash |
| 命题 | 单一 claim、subject/predicate/value、适用范围；未知不猜 |
| 类型 | fact/decision/preference/gotcha/task-state/hypothesis 等语义分类，映射现有 kind 由规格定义，不直接扩 kind |
| 断言 | 谁说的、是否引述、否定/条件、建议/同意/完成/撤销，不能靠关键词拍板 |
| 时间 | observedAt、明确给出的 validFrom/validTo、未来事件时间；相对时间需时区与参考时间，无依据留空 |
| 证据 | source eventId、规范化脱敏版本 hash、原文精确 span、必要邻接上下文；工具结果带结果/退出状态 |
| 关系 | 支撑/纠正/撤回的候选或记忆 ID，必须来自输入允许集合；不能凭空造 ID |
| 血缘 | provider/model 标识、prompt/schema 版本、配置 hash、运行 ID、父来源、trust/taint |
| 工作流 | pending/rejected/accepted，拒绝理由、人工操作者及时间；接受状态与 trust 独立 |

source span 的定位基于版本化、规范化且脱敏后的证据文本；原始字节不公开。源文件变化时 hash 不匹配应 stale，不自动把 offset 指向新内容。

### 3.3 六道抽取防线

1. **结构**：严格 schema、枚举、长度、scope 和 ID allowlist；schema 正确不等于事实正确。
2. **证据存在**：span/quote/hash/event 真能定位；证据不完整或已删除，阻止接纳及装配。
3. **语义核对**：检验 claim 是否受证据蕴含、角色是否正确、否定/条件/时间是否保留。可用第二次模型审查提出异议，但它不是可靠裁判。
4. **冲突与纠正**：同 subject/slot 的不同值生成待裁决；“不用 A，改 B”“尚未做”“只讨论过”独立用例。新消息不能因更晚就覆盖已确认事实。
5. **接纳**：v2.0 的抽取候选一律人工逐条/显式批量复核后才写长期库；无自动晋升。关键决策、偏好、删除及信任提升保留明确人工动作。机器验证过的非事实导航可在独立 references 展示。
6. **传播控制**：摘要/归纳继承来源与最低信任，不因派生洗白；纠正/撤回后旧候选、向量、摘要和 pack 缓存失效，查询时再次检查状态。

“用户表示测试通过”只能抽取为用户报告；“工具退出 0”只证明该命令的结果，不证明全项目正确。助手提出计划不等于用户已批准，模型 confidence 不视为校准概率。

### 3.4 失败与 Prompt 管理

- 超时、空响应、解析失败、token 截断、证据不支持、无可记内容分别记录状态；只对已定义的瞬时故障有限重试。空抽取不能掩盖模型故障。
- 失败保留输入游标和可重试引用；规则 fallback 只出带 degraded 的导航/候选，不能降级后悄悄晋升事实。
- 抽取、核对、摘要用独立版本化 Prompt 与 schema；模板中含否定、建议、纠正、条件、无信息的中英反例。
- Prompt 变更在 dev 集调优，test 集只评估；保留模型响应快照（脱敏、受控保留），重放响应后验证确定性后处理。
- 不承诺重新调用 LLM 逐字相同；确定性要求仅适用于冻结输入/候选/时间/配置的校验和装配。

## 4. 长期记忆与纠错

保留 append-only 与当前 supersede/forget；抽取接纳经过现有四道门，不绕过限额、脱敏和 trust。

P2 引入显式 correction/retraction 的关联语义及可重建依赖索引；在此之前，P1 保守地按 scope 的真相层修订版本使相关派生缓存整体过期，重新构建且读时过滤，不能只删一个向量便认为传播结束。

候选接纳后保留其证据和审核引用，证据只证明出处；人工接受不自动赋予 T0。scope 是分类而非权限边界，本期仍是个人部署。

## 5. RAG 与上下文装配

- 首先复用 BM25 / embedding / RRF，比较真实中文改写、标识符、时间更新；检查实际语义道是否 enabled。不得在 semantic-disabled 下报告混合检索效果。
- 检索前后均校验 scope、asOf、status、trust/taint；已撤回/失效信息不能因为相关性高进入 current facts。
- pack 输入：任务查询、scope/task、asOf、includeLedger、目标 tokenizer 和 tokenBudget；目标 tokenizer 不支持时显式报错或保守估算并标 estimated，不伪称精确预算。
- facts、currentTask、references、unresolved 分区；latest checkpoint 不覆盖有证据的历史，却控制当前状态投影；冲突不偷偷选赢家。
- T2 来源原文默认不注入，包括 ledger 引文；可用结构化且显式标记未验证的 references。显式允许原文仍沿用现行隔离/转义策略，不把围栏当安全保证。
- 优先稳定索引与短证据片段，按需 expand 原文。返回 excluded 原因、来源、预算消耗、缺口及降级状态。
- reranker/query rewrite 只在 P3 消融证明必要时启用；模型重写 query 不得改变 scope 或证据边界。
- 每次 pack/inject 留回执：record/version IDs、来源 hash、asOf、配置/模型/Prompt/tokenizer 标识、预算、excluded、packHash；不把正文秘密复制到审计。
- 区分 preview/generated/exported/delivered/host-ack。无宿主 ACK 只能声称生成或交付，不能声称“Agent 确实看到了”。

## 7. 验收与实验纪律

以下是项目发布门槛，不是已测成绩。样本数量与门槛是为本期准确性优先设定的初始工程标准；P1a 在看 test 结果之前冻结到配置。不能失败后挑样本/改阈值来宣布通过。

| 层 | 冻结要求与发布标准 |
|---|---|
| 语料 | 至少 200 个中英对话场景，按来源/场景家族隔离 dev 100、test 100，近重复不得跨集合；test 至少 200 条可抽 gold claim、50 个无可记内容场景（可与其他场景类型交叉），防全拒绝刷精度 |
| 标注 | 每条 gold 包含角色、类型、范围、状态、时间、证据、应拒绝原因；两次独立标注后人工裁决；无人完成复核则不能称 gold 验收通过 |
| 对抗覆盖 | 否定、建议未接受、后续纠正、条件/假设、工具失败、跨项目同名、跨段指代、时区/相对日期、注入、截断缺口每类 test 至少 10 例；场景可多标签 |
| 抽取精度 | 在人工接纳之前评估模型+校验后的候选；test claim precision ≥98%、recall ≥90%；固定配置至少 3 次运行分别达标，同时报告计数和 Wilson 95% 区间，非只报百分比 |
| 严重错误 | test 中无依据事实、角色错归、否定反转、建议变批准、未做变已做、跨 scope 泄漏、撤回信息当当前事实，任一出现即阻断发布；零观测不等于总体零错误 |
| 可追溯 | 所有可接纳候选的证据引用可解析率 100%；源 hash 漂移、秘密、缺失来源、非法 ID 一律阻断。精确引用不是语义正确的替代指标 |
| 状态/纠错 | 专项回归全部通过，纠正后旧值不进 current facts；历史 asOf 可回查；重复 capture 不重复晋升；来源删除后派生及 pack 不残留 |
| 装配 | 冻结输入/候选/配置/asOf/tokenizer 后逐字节复现；精确模式不超 tokenBudget；关 includeLedger 不混入段；预览不冒充交付 |
| 效果 | 至少 30 个脱敏跨会话任务、固定回答模型/预算，比较无记忆、最近窗口、BM25、混合检索、混合检索+pack；dev 调优、test 冻结，每任务至少 3 次模型采样 |
| 发布收益 | 相比同预算混合检索，pack 必要证据覆盖率不下降、token 中位数至少下降 20%，任务成功率不下降；三者均满足才称装配收益成立；报告配对差值/区间，样本小不宣称统计显著 |
| 成本 | 报抽取/核对/检索/装配/回答分项调用数、token、金额及 P50/P95 延迟；P1a 试跑后冻结成本和超时上限，未配置拒绝大批量 LLM 运行 |

模型评分只作辅助，涉及严重错误与分歧须人工复核。人工接受前后成绩分别报告，不能用人工修好的结果冒充自动抽取精度。固定小集只验证该集；扩展 LongMemEval cleaned 的公开子集/完整集时标明版本、大小与可比条件，禁止把子集成绩写成完整榜单成绩。

多标签/集合匹配按冻结的原子命题和证据规则去重：同一 gold claim 只计一次 TP，额外重复候选计 FP，未支持但在声明支持范围内的 gold 仍计 FN。若收窄能力范围，先发布新范围与新评测版本，并保留旧集完整结果，不在原 test 上删除难例。

## 8. 可行性、取舍与停止条件

- 可行：现有存储、MCP 和模型 port 已够用；新工作集中在证据候选和评测，无需另起平台。
- 主要成本：标注/复核、中文指代和时间、候选生命周期、缓存失效。不能以“有 JSON 输出”估算抽取已完成。
- P1b precision 未达标：缩小支持的内容/语言/来源范围，明确 unsupported，继续调 dev；不默认放宽精度或开启自动晋升。recall 不达标不能靠全拒绝发布。
- pack 无收益：保留原 brief，发布实验与负面结果，停止为 UI/新模块继续扩张，不强行宣传节省。
- 只允许一条主线、一个首发来源；独立审核者不能由主代理自行冒名。任何真实模型试验前确认成本配置，不用真实私密历史作公共样本。
- zero-runtime-dependency 内核继续保留；未来确需 tokenizer/其他库先 ADR 评估依赖范围，不能为零依赖牺牲正确性，也不在本文偷偷引依赖。
