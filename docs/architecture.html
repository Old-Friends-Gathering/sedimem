strata
把「记忆」当数据库治理，而不是当 prompt 攒

DSH / Codex CLI / Claude Code 三端共用一份本地记忆。重点不是「检索得准」， 而是治理得住：去重、冲突失效、过期不删只失效、投毒不进上下文、库自己会随使用收敛。

v0.3.0 当前版本 Node ≥ 22 运行时 零依赖 只用 node: 内置模块 MIT 许可 271 项测试

01 为什么是 strata

常见记忆方案的问题不在召回率，而在「库会越用越脏」。strata 把每一条脏化路径都变成了有裁决编号的规则。

常见做法的问题strata 的做法
记忆越攒越多，重复/矛盾条目一起进上下文写入门控：hash 短路 → 同 slot 判等 → 近重复 noop + 冲突 slot 失效
换措辞的同一条事实被判成「冲突」在线只做零误杀去重；语义判断交给正在运行的 Agent（dedupe_scan → curate_apply），零 API 成本、可离线
只有「删掉」这一种清理手段真相层不可变；过时 = 打 validTo 失效，删除 = 墓碑 + 延迟物理清理
记忆里被塞进指令型内容，悄悄影响后续会话写入打标 + 读路径默认遮蔽（[suspicious withheld]）+ brief 逐行复检
换个客户端就「失忆」MCP 是唯一缝；三端同读写一份真相层，memory_scope 解决常驻进程 cwd 固定导致的分库错位

刻意不做

non-goals

embedding 语义检索（v0.2 的 EmbedderPort 再说）、多机同步、加密存储、多用户隔离（scope 是分类不是权限）。

技术标识保持不变

backward compatibility

产品名是 strata，但 CLI 仍是 memo、环境变量仍是 MEMO_*、MCP 工具名仍是 memory_*、serverName 仍是 memo——改这些要同步三端客户端配置与历史分库目录。

02 四个地层

名字来自地质学：记忆像地层一样沉积，而不是被反复改写覆盖。四个地层分别承担真相、派生、失效标记与维护。

沉积层 · 真相

$MEMO_HOME/items/<scope>.jsonl

每次状态变更追加一条完整记录快照，同一 id 最后一行胜出。永不删物理行，「改过去」= 追加新版本。

只追加 · 可 as-of 回看任意时点

派生层 · 索引与摘要

index/ · views/ · brief/ · metrics/

倒排索引、SQLite FTS5、L2 场景块、L3 画像、brief 渲染、metrics 快照。随时可从真相层重建，坏了不丢数据。

可重算 · 删掉目录也能逐字节复原

不整合 · 失效标记

validTo / status

过时的事实失效而非删除：superseded / tombstoned / disputed 带 bi-temporal 时间戳，asOf 可回看任意时点。

宁并存，不静默删

风化层 · 维护

nightly · dedupe · compact

慢速、可离线、可重放：夜间整合做 TTL 过期与配额淘汰，去重扫描产候选簇由 Agent 当裁判，压实在三重条件都满足时才动手。

由 Agent 裁决，而不是纯算法

三条明确不变式

  • 真相层不可变：只追加；「改过去」= 追加新版本，不得原地修改或删除行。
  • 派生层可丢弃：删掉 views/ 后 memo view rebuild 必须逐字节复原（eval I21 守）。
  • 能力在 Ports 后：Storage / Index / Judge / Renderer / Clock 五个扩展点，换实现不改 core。

04 写入路径

写入不是「append 一条」，而是一次带四个出口的判定。decideWrite() 只吃 record + 候选集，不碰存储——它是策略的唯一落点。

contentHash 短路 noop_duplicate

同 scope 下已有 active / disputed 记录且 sha256 相同（归一化文本 + subject + predicate + value），直接判重，不新增行。

同 slot 判等 noop_same_value

slot = scope + subject + predicate 归一化。同 slot 且归一化 value 相等，说明是同一事实的重复表述。

近重复防线 noop_same_value reason=near_duplicate

文本相似度 ≥ policy.dedupe.nearDupThreshold（默认 0.85）判为近重复，并给原记录打 variant 标签。必须在冲突判定之前——否则「同事实换措辞」会沦为 disputed 垃圾。

冲突判定 disputed supersede created

同 slot 但值不同：合法状态推进（结构化 slot 且新值更晚）→ supersede；无法判定谁新 → 双方 disputed，等 Agent 裁决。都不是 → created。

为什么要「零误杀」：在线判定一旦误判，就会把一个真实事实压掉，而且没有人工复核环节。 所以 semantic 判断被刻意移出写路径——交给正在运行的 Agent 做离线裁决（dedupe_scan 只出候选，curate_apply 才落判定）。

05 数据模型

一条记录是不可变的快照；状态的每一次变化都是新的一行。7 条不变式写在 docs/02，是实现的唯一权威。

字段含义
idULID，时间有序、可排序
scope分库，形如 repo:strata / dir:desktop / user:x / global:x
kind数据驱动：fact / pref / decision / gotcha / state，来自 config/policy.json
text · subject · predicate · value人类原句 + 结构化 slot（缺省时 slot 记为 text/text，即 unstructured）
statusactive / superseded / tombstoned / disputed
validFrom · validTobi-temporal 生效区间；asOf 查询按它过滤
contentHashsha256: 前缀，写入门控的短路键
sourceRefs可选溯源：非空 ULID 数组、无重复、不得自引；只在 L3 画像这类派生记录上出现
hits · tags · confidence召回计数（批量落盘）、清理标签（quota / purge / variant）、置信度

状态迁移

active ──supersede──▶ superseded ──forget --purge──▶ tombstoned ──compact（三重条件）──▶ 物理删除
active ──冲突且无法判新旧──▶ disputed ──Agent 裁决──▶ active / superseded
supersede 拒绝 tombstoned。否则一次普通写入就能把 purge 语义打断——墓碑是删前的最后一道状态，不能被「改成别的值」复活。

06 读路径

三种读，三种预算。检索不是越宽越好，注入进上下文的每一个字符都要有配额。

search

BM25 · kind 权重 · 半衰期衰减

tokenize 中文 2-gram / 英文词，BM25 打分后按 kind.weight 加权、按 halfLifeMs 做时间衰减。默认 limit=10。

每次检索追加一条 search 事件（只存 qHash，不存原文）

brief

≤ 80 行 · ≤ 8000 字符

按 kind 分组 + 近期记录，超限先砍散条 → 再砍 L3 → 最后砍 L2。视图缺失时降级为扁平渲染（视图是加速层，不是依赖）。

配额：L2 25% / L3 15%

tier0

≤ 800 字符 · 一条一行

极窄注入的目录视图：每行带完整 ULID，供 memory_get 反查原文。截断 id 等于让证据链失效。

排序：hits 降序 → createdAt 降序

投毒防线

写入时按 policy.suspiciousPatterns 打标；读路径默认遮蔽 text / value / subject / predicate / source.quote 五个正文字段， 统一占位 [suspicious withheld]。只遮 text/value 是不够的——把 payload 挪进 subject 就能原样出网。

07 分层视图（L2 / L3）

v0.3 的主题：结构层用确定性算法，LLM 只写「可重算的表述层」。同一份真相层两次构建，字节必须相同。

L2 · 场景块

views/<scopeKey>/L2.jsonl

按 slot 分组，对无结构记录做相似度聚类。blockId = sha256(key).slice(0,12)，builtAt 取记录里最晚的 createdAt——不是 Date.now()，否则两次构建字节不同。

不变式：Σ block.recordIds.length === sourceCount

L3 · 画像

固定预算 · 强制溯源

由 Agent 写草稿：sourceRefs 必填且为 ULID、text ≤ 2000 字、confidence ∈ (0,1]。预算 maxCallsPerRun=20 / batchSize=10 / TTL 30 天。

成本有上界：调用次数是策略常量，不是感觉
可重建性是被测试守住的，不是口号。删掉整个 views/ 目录后 memo view rebuild 必须逐字节复原，由 eval I21 验证。

08 维护的其中三条路

「自我迭代」不是修辞：库的健康度由三条可离线、可重放的路径维持，每条都有明确的触发条件与不可逆边界。

路径做什么边界
nightly
每天 03:30		 TTL 过期、配额淘汰（墓碑打 quota）、hits 落盘、brief 重建、metrics 快照 只报告去重候选簇，不自动裁决（裁决归 Agent）
dedupe_scan → curate_apply 按 slot 分组 + 两两相似度并查集聚簇，产出 pairs 与 strength；Agent 逐对裁决 扫描只读；merge 是非破坏的（败者 superseded 且真相层保留），宁判勿漏
compact 物理清理：写 .tmp → fsync → rename 原子替换，替换前备份 .bak.<ts> 三重条件全满足才删：status=tombstoned ∧ tags 含 purge ∧ validTo < now − 7d
events.jsonl 永不被 compact 删。它是审计面——「这条为什么被删」永远可查。这是「不可变」在删除语义上的延伸。

Windows 落位的两个坑

  • 真相层文件名不能含冒号。scope 恒含 :，而 Windows 把它当 NTFS 备用数据流分隔符——items/repo:strata.jsonl 会变成文件 repo 的一个数据流，readdir 看不见它、copyFile 直接 EINVAL。现在由 config/paths.js 统一映射成 repo+strata.jsonl（裁决 58），POSIX 行为不变。
  • 计划任务默认会「空闲即停」。StopOnIdleEnd 默认为 true，机器一空闲任务就被结束且退出码为 0，看起来像服务自己挂了；直接用 node.exe 当 action 还会弹控制台窗口。正确姿势是 -DontStopOnIdleEnd + wscript 隐藏启动 + 一个循环守护进程兜住 exit 0。
