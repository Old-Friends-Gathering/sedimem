终态分层总览

自下而上一条写路径（来源 → 四道门/抽取管线 → 真相层），自上而下一条读路径（真相 → 检索 → 装配 → 宿主 Agent）；端面贯穿读写，评测与审计两条横切轨全程跟着。颜色只回答一个问题：哪些已经上线，哪些还没建。

03

候选生命周期（P1b 核心）

从原始转录到可信 facts，一条候选要走完六道防线、一次人工接纳、一次独立提权。这是本次重构与竞品（Mem0 / claude-mem 等 ADD-only 抽取）的本质差异：抽取不落库，复核才落库，提权才可信。

DSH transcript · 原始来源

是什么：DSH 会话转录（zstd 多帧），P1a 唯一放行的首个验证来源。标识：sourceEpoch（来源纪元，撤销时过滤所有新读面并禁止自动重新 capture）+ rangeId（抽取区间）。边界：原文存在只证明出处，不证明为真——因此只作为证据层输入，不直接生成事实。其他来源（任务账本、P2 只读导入）必须走同一抽取管线，不同仅在入口。

LLM 抽取 · 锁外调用【P1b】

时序约束：数据锁不覆盖 LLM 网络调用——锁外抽取、锁内核对落盘（计划 §3.5）。血缘（候选字段）：provider、model、prompt 版本、配置 hash、runId，全部随候选落盘，评审时可追溯到具体一次抽取。闸门：真实模型调用前必须先配成本 / 并发 / 重试 / 配额闸门（§8），LlmPort 新用途与限额进 policy。规约：抽取不是「把聊天缩短」——必须保留谁说的、关于谁、建议还是决定、何时适用、依据、是否已被纠正。

候选 candidate · 字段语义（计划字段，非现行 schema）

核心字段：candidateId、schemaVersion、scope、输入范围 hash。内容：单一 claim（一条候选只说一件事）；类型 fact / decision / preference / gotcha / task-state / hypothesis（与现有 kind 的映射由 P1a 规格定义，不直接扩 kind）。断言：谁说的、引述、否定、条件、建议｜同意｜完成｜撤销。双时间：observedAt + assertedValidFrom/To（业务时间）独立于 MemoryRecord.validFrom/validTo（系统可见区间），防止 asOf 穿越。关系：关系 ID 必须来自输入允许集合，不得幻觉引用。工作流：pending / rejected / accepted 与 trust 完全独立。

六道防线 · 抽取质量的结构化保证

① 结构 schema：候选必须通过机器可校验的结构定义；② 证据存在：每条 claim 携带 span/hash/eventId，必须能在原文中定位，证据解析率门禁 100%；③ 语义核对：claim 与证据语义一致，不允许「证据说 A、候选写 B」；④ 冲突与纠正：与既有记录冲突时走纠正路径而非静默新增；⑤ 人工接纳：accept 后仍 T2，只进 references；⑥ 传播控制：摘要继承最低信任，纠正后旧候选/向量/pack 缓存失效。前四道机器执行，第五道人类执行，第六道跨波次生效（P1b 起、P2 完整）。

人工复核 CLI【P1b 首发，UI 后续】

完整流程：candidates list → show → diff → accept / reject → status。交互红线：逐条展示、不可默认勾选——批量操作只允许批量「查看」，不允许批量「接受并提权」。落点：accept 只把候选置为 accepted 并以 T2 追加进真相层（references 可见）；提权是另一次独立动作。证据：复核记录本身入审计事件流，可回放。

T2 落库 = 唯一提交点【P1b】

幂等五元组：sourceEpoch、rangeId、extractionRunKey、candidateVersion、acceptOpId。CAS 校验（同一数据锁内）：candidateVersion + evidenceHash + expectedTruthRevision 三者匹配才允许追加；长期记录成功追加即为提交点。no-op / merge：需持久收据（opId → 目标记录），不能只留内存结果。区间幂等：重叠写入返回 E_ALREADY_CAPTURED 且零写入。崩溃恢复：无法判定提交结果时标 recovery-required（见旁路节点），带恢复测试覆盖。

trust promote → T1 facts【v1.4 已上线】

动作：memo trust promote，带理由，逐条执行——这是 T2 升 T1 的唯一路径（P0b B2 交付）。与 accept 的关系：accept 是候选工作流状态（accepted），promote 是信任状态（T1→），两者独立、先后两次人工确认。效果：T1 记录才可进 memory_pack 的 facts 分区；T2 记录只能以 references 出现。对抗背景：首轮审核 A01（blocker）指出「accept 不提升 trust 却无可信 facts 路径」的矛盾，最终以「二次独立 promote」收口。

reject → 拒绝样本留存

不丢弃：被拒绝的候选作为评测负例持久留存（按数据地图登记可删性），进入冻结测试集的对抗维度（建议未接受、后续纠正等十类）。回放：每次抽取管线迭代后在拒绝样本上回放，防止同类错误复发。审计：拒绝动作与理由写入事件流（P1b 交付），与 accept 对称。

recovery-required · 显式恢复态

触发：提交结果无法判定（如锁内 CAS 核对后进程崩溃，追加是否落盘未知）。纪律：该状态禁止自动重试——自动重试可能把同一段输入重复入库，破坏区间幂等。恢复：由人工按 opId 对账后推进；恢复路径有专项测试覆盖（对抗修订 A03 / D02）。与 reject 的区别：reject 是「人看了，决定不要」；recovery-required 是「系统不知道结果」，两者都阻断传播，但语义与处置不同。

04

路线门槛与放行

P1a 是当前唯一入口；P1a 结束前九项决策必须冻结，缺一不得开 P1b。所有门槛数字是冻结目标，不是已测成绩。

P1a 结束前冻结九项：候选状态 · 幂等协议 · 证据范围与删除语义 · 双时间 · kind 映射 · 信任提升路径 · 精确 tokenizer（含目标模型组合）· 成本容量上限 · 测试切分与打分规约。

七类严重错误（评测中任一出现即阻断，不看总分）：无依据事实 · 角色错归 · 否定反转 · 建议变批准 · 未做变已做 · 跨 scope 泄漏 · 撤回当当前。

本轮放行边界：只放行 P1a 的规格、标注准备与最小试跑。不建 v2.0 版本目录、不切 CURRENT；v2.0 规格先写 docs/design/v2.0/ 草案（planned），等 CURRENT 切换时才同步现行 docs/02 / 04 / 07 / 12。

发布收益三条件（端到端实验，三项同时满足才谈发布）：pack 证据覆盖率不降 · memory token 中位数降 ≥20% · 任务成功率不降。对比组五档（无记忆 / 最近窗口 / BM25 / 混合 / 混合+pack）共享同一份人工接纳与 trust 结果，成对比较、每组 ≥3 次运行。
