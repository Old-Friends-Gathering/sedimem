## 0. 三件事的共同点

三件事都在问同一个问题：**在有限的注意力/上下文预算下，怎么让记忆更值钱**。
所以本版不止加三个功能，还要把「值不值」变成可测的数字——否则下一版又会凭感觉调。

## 1. 方向 A：让每条记忆短而明确（写侧契约）

**结论先行**：读侧已经省（`tier0` 800 字符一条一行、`brief` ≤80 行、`memory_get` 按需取全文），
短板在**写侧**——现在允许一条 4000 字符的长段塞进多个事实，而且超长是**静默截断**。

### A1 契约（改 `versions/v0.6/src/core/record.js` + `config/policy.json`）

| 规则 | 值 | 行为 |
|---|---|---|
| `value` 上限 | **300 字符** | 超限 → `E_VALUE_TOO_LONG`，错误信息给「拆成几条」的示例；不再静默截断 |
| `text` 软限 | **600 字符** | 超限不拒，打 `long-form` 标签（可查询、可统计） |
| `text` 硬顶 | 4000（保留） | 超硬顶仍拒（防滥用），但错误码从静默截断改为 `E_TEXT_TOO_LONG` |
| `title` | 结构化记录**必填**（≤40） | 缺 → `E_TITLE_REQUIRED`；这是 `makeLabel`、`brief`、图谱标签的唯一可信来源 |
| 疑似多事实 | unstructured 且按 `。；;.` 切分 >3 句 | 写入成功但返回 `hints:['多事实，建议拆分']` 与 `factsSuspected: N`（软信号，不阻断） |

### A2 MCP 工具描述与 `INSTRUCTIONS`

`memory_write` 的 schema 描述改写为：「**一条记忆只记一个事实**；多事实请多次调用；
`value` ≤300 字；结构化记录必须给 `title`」。`INSTRUCTIONS` 补一条「写入前先问：这句话能不能再拆？」

### A3 验收（机械）

`eval` 新增 **I37 `i37-brevity-contract`**：
1. 301 字 `value` → 拒，错误码 `E_VALUE_TOO_LONG`；
2. 700 字未结构化 `text` → 写入成功且 `tags` 含 `long-form`；
3. 结构化记录无 `title` → `E_TITLE_REQUIRED`；
4. 4 句长文 → `factsSuspected >= 3`；
5. 存量长记录（v0.5 迁移来的）**仍可读、可 search**（向后兼容）。

指标（`stats` + nightly 快照新增）：`meanTextChars`、`p90TextChars`、`longFormRatio`、`titleCoverage`。

### A4 存量数据

**不改写真相层**。迁移只做两件事：给现有 >600 字符的记录补 `long-form` tag（追加式补丁记录），
`memo doctor` 报「存量长记录 N 条」。这一点写进 DELTA 的「刻意不做」。

## 2. 方向 B：开发期临时记忆库（session scope）

**结论先行**：不自己造压缩器——DSH 已经有 `@deepseek-ai/dsh-compaction-basic`
（`thresholdRatio: 0.8`、`retainRatio: 0.16`、per-model `retainTokens/headroomTokens`），
并且发 `compaction/summary` 事件（`{compactionId, summary: ContentBlock[], shadowedRange,
shadowedTokenCount, provider, model}`，本机 asar 已核实）。插件订阅这个事件即可**零额外 token** 拿到摘要。

### B1 数据模型（sedimem 侧，宿主无关）

- 分库命名：`session:<id>`，`id` = 战役名（多 agent 共享一个库，而不是一个 DSH session 一个库）。
- 记录形状（复用现有 `MemoryRecord`）：
  - **1 条 `state`**：`subject=<id>`、`predicate=checkpoint`、`value=最新 checkpoint 全文`、
    `tags:['scratch','session:<id>']`；每次更新 `supersede` 自己（版本链天然可回溯）。
  - **N 条 `decision`/`gotcha`**：从 checkpoint 的 `Critical Context`、`Errors and Fixes` 拆出，一条一句。
- checkpoint 结构**冻结为 8 段**（与 DSH 冻结的 summary 结构一致）：
  `Intent / Concepts / Files / Errors and Fixes / Pending Jobs / Current State / Next Steps / Critical Context`。
- 明确契约：**临时库是派生数据**，可从宿主会话日志重建，可整体丢弃；不污染 `repo:<name>` 真相层。

### B2 CLI（纯 sedimem，先做，可 100% 单测）

```
memo session start <id> [--scope repo:<name>]   # 记录战役起点（workdir、分支、目标）
memo session list [--json]
memo session show <id>                          # 最新 checkpoint + pending
memo session promote <id> [--as decision]       # 把有长期价值的条目晋升进项目主库
memo session close <id>                         # 打 tombstone + 写 closedAt
memo session sweep [--ttl 7d] [--dry-run]       # nightly 调，清理过期未晋升的
```

### B3 DSH 插件（触发器）

`plugin/dsh-sedimem` 新增 `lib/session-memory.js`：

| 触发 | 实现 | 备注 |
|---|---|---|
| 首选 | 订阅 `compaction/summary` | 拿现成 summary，零额外 token；把 `shadowedTokenCount` 累计写进 `state.hits` 之外的自有字段（`source.quote` 存 compactionId） |
| 兜底（非 DSH 或其他宿主） | CLI `memo session snapshot --from <file>` | 事后压缩，解决跨会话丢失，不解决会话中省 token |
| 阈值 | 默认吃宿主 `thresholdRatio`（≈窗口 80%），不写死 30k | 用户要「约 30k」时配 `session.thresholdTokens: 30000` 即可覆盖 |
| 开关 | `session.enabled=false` 默认关 | 与 `inject.enabled` 一致，装了不等于开了 |

### B4 验收

`eval` 新增 **I38 `i38-session-checkpoint`**（用假 `compaction/summary` 输入跑插件纯函数）：
1. 8 段缺 3 段 → 仍生成 checkpoint，缺段写 `（本段缺失）`；
2. 同一 `session:<id>` 第二次写入 → 版本链长度 = 2，`active` 仍 = 1；
3. `promote` 后主库出现 N 条 `decision`，临时库对应条目 `superseded`；
4. `sweep --ttl 7d --dry-run` 只报不删；真删后 `stats.total` 下降且 `events` 留痕；
5. 临时库清空后 `brief`/`search` 不报错（空库路径）。

**I39 `i39-session-host-parity`**：CLI 与插件两条路对同一份摘要产出的 checkpoint 字节一致（保证「可从日志重建」）。

## 3. 方向 C：分库选择在页面间保持

### C1 根因（已核实）

`versions/v0.5/ui/app.js:520` 的 tab 点击写 `location.hash = '#/' + r`，**丢掉 `?scope=`**；
读口只有 `currentScope()`（`:18`）一处，直接从 hash 解析。

### C2 修法（推荐 B：粘性分库）

新增 `versions/v0.6/ui/scope.js`（**纯函数，可单测**，不碰 DOM）：

```js
export function resolveUiScope({ hash, stored, serverCurrent, known }) {
  const fromHash = readScopeFromHash(hash);
  if (fromHash && known.includes(fromHash)) return { scope: fromHash, source: 'hash' };
  if (stored && known.includes(stored)) return { scope: stored, source: 'storage' };
  return { scope: serverCurrent ?? known[0] ?? '', source: 'server' };
}
```

`app.js` 改动 5 处：tab 点击带 scope、`currentScope()` 换成 `resolveUiScope`、切换分库写
`localStorage['sedimem.ui.scope']`、`loadScopes()` 用返回值渲染下拉、启动时若 hash 无 scope 则
`history.replaceState` 补上（不产生历史条目）。

### C3 验收（6 条机械检查）

1. `#/today` → 点「图谱」→ 请求里 `scope=` 与原来一致；
2. 图谱 → 搜索 → 卫生 → 今日，四页 `scope` 一致；
3. 直接开 `#/hygiene`（无 query）→ 用 localStorage 里的分库；
4. 清空 localStorage → 回落到 `/api/scopes` 的 `current`；
5. 分库被删（localStorage 里是旧值）→ 静默回落到 current，不 404；
6. 多标签页：另一页切分库后本页刷新跟随（`storage` 事件）。

## 4. 数学/金融标定（轻量轨道，不引入运行期依赖）

只做三条**能改善默认参数**的，其余明确不做（理由见调研报告）：

| 轨道 | 做什么 | 产出 | 验收 |
|---|---|---|---|
| M0 埋点 | `compact`/`search` 事件补 `tokensIn/tokensOut/perKind` 计数 | 后续所有标定的数据基础 | `events.jsonl` 新字段可被 nightly 聚合 |
| M1 生存分析 | 用 `hits` + `validTo` 做 Kaplan–Meier / Weibull（右删失），按 `kind` 分层估半衰期 | `tools/calibrate-decay.mjs` → 新的 `kinds.*.halfLifeMs` 默认值 + 报告 | 新半衰期在回放集上的「过期命中率」不高于旧值，且 `active` 规模下降 |
| M2 滞回压缩 | 触发从「固定阈值」升级为「上阈值 p85 / 目标 p50 / 滞回带 ≥3×单轮增量」 | `session.trigger.mode = fixed \| hysteresis` | 回放同一段用量序列，压缩次数不增加而尾部占用（>90% 窗口的步数）下降 |

引用：newsvendor（brief 行数）与 VaR（爆窗预算）**本轮不做**——缺 token 埋点，
做完 M0 才谈得上；DPP/子模选择（brief 选哪些而不是 top-k）留 v0.6.1，因为它需要 qHash 回放集先建好。

## 7. 风险与回滚

| 风险 | 处理 |
|---|---|
| A 的 300 字上限拒掉现有客户端的写法 | 先发 `0.6.0-rc` 观察 `E_VALUE_TOO_LONG` 频次；`policy` 可临时放宽到 500 |
| B 的临时库与主库语义混淆 | scope 前缀 `session:` 强隔离；`brief` 默认不读临时库，除非显式 `--include-session` |
| 插件订阅事件在宿主升级后失效 | 三段防御式注册（`ctx.on('session/event')` → `onEvent` → 关闭并打日志），失败不影响路由 |
| C 的 localStorage 与多标签页竞争 | `storage` 事件监听 + `resolveUiScope` 纯函数（6 条用例锁行为） |
| 数学轨道跑偏成学术玩具 | 每条必须有「机械验收 + 回滚一个 policy 字段」两件事，做不到就不合 |

## 8. 明确不做

1. 不做自动切分长记录 + 重建历史（需要 LLM，违背零依赖；`append-only` 会被破坏）；
2. 不自己实现上下文压缩器（DSH 已有 `compaction-basic`，重造只会更差）；
3. 不做 Kelly / MDP 求解器 / Information Bottleneck / 在线 Markowitz——本版没有数据量支撑；
4. 不做跨设备同步与团队共享（定位是个人本地）。
