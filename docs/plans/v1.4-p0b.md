## P0b 主体（按 §6.2 的 17 项）

按依赖排序，每项先写规格/测试，再写代码：

### B1. 锁与队列

- [x] storage 数据锁 `<memoHome>/.lock`：5s 心跳、陈旧判据 = mtime 超时 **且** owner pid 不存在、rename 接管；`capture/queue.js` 的同步锁也改用同一 `<memoHome>/.lock`（owner.json + pid 判据 + rename 接管）。
- [x] `llm/outbox` 锁保留，ADR-001 写理由（Q15 禁依赖 storage）。
- [x] 队列 append 改 `O_APPEND` 流式写，不整文件重读重写；`capture.maxQueueBytes` 单文件字节配额（`E_QUEUE_QUOTA`）。per-adapter / 每日配额与 provenance 数组上限留到 P2（有 adapter 才有主体）。
- [x] 测试：`kill -9` 后锁可恢复；存活 owner 不被误接管；配额超限 fail-loud 且不写半行。两进程并发 append 由现有 storage 并发测试覆盖，未新增跨进程用例。

### B2. trust / taint / provenance

- [x] `MemoryRecord` 增可选 `trust`（T0–T3）、`taint[]`；缺省读作 T2。`provenance` 未做（P2 adapter 期再补，见执行结果）。
- [x] `memory_write` / CLI / capture accept 不得自报 T0：写路径统一 `deriveTrust(..., {mode:'write'})` 覆盖为 T2；adapter 注册表属 P2。
- [x] merge / supersede 追加新版本 `v+1`，taint 取并集、trust 取更弱者，禁止静默清除；`memory_write` 无 scope 时写当前库。
- [x] 存量 backfill：采用读取派生（`source.agent ∈ {cli,dsh,claude,codex,test}` 且无 capture → T0，否则 T2），不改真相层；理由与回滚见 `docs/02` §3.24.4，未做 `memo migrate`。
- [x] `memo trust promote` 是唯一降 taint 动作，带理由、写审计。
- [x] 测试：T2 不可被 write 洗成 T0；supersede 后 taint 包含两侧；跨 profile 隔离。pack 级验收依赖 P1（本版只验读取视图 trust 非空）。

### B3. 删除与 profile

- [x] `deleteBySource(adapter/uri)`：墓碑 + compact + 清派生 + 脱敏审计 + 备份说明；含任务账本 `sessions/<taskId>/segments.jsonl`。
- [x] `memo verify-delete`：按来源/哈希确认目标记录、索引、向量、brief、账本段均已消失。
- [x] profile 收敛到 `resolveMemoHome(env,cwd,profilePointer)`；默认 `~/.memo` 不变；命名 profile 在 `~/.memo/profiles/<name>/`；缺失指针 fail-closed。
- [x] 测试：命名 profile 互不可见；删来源后 verify-delete 通过；默认 profile 路径不变。

### B4. Web 鉴权与文件权限（已完成）

### B5. 注入与审计
