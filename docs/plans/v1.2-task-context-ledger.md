# v1.2 计划 v2（对抗审核后修订）：任务上下文账本

> 被审版本：本文件 v1（五路红队结论见 `docs/reviews/v1.2-adversarial/`，处置见同目录 `RESPONSE.md`）。
> 定位不变：**任务库 = 跨会话的上下文账本**。每个会话把"已被消费掉的上下文"折叠成可展开的段，下一个会话读账本接上。
> v1 有 8 条阻断（transcript 读不了、value 装不下、close 会卡死……），v2 全部改掉。

## 0. 前置事实（已实测，不是假设）

| 事实 | 值 |
|---|---|
| 本会话 transcript | 63.9 MB / 34,184 事件 / 4,908 assistant 消息 / 4,835 工具调用 |
| 压缩次数与挤出 | 145 次，累计 ≈295.7 万 tokens（单次最大 121,479） |
| DSH 事件形状 | `{type:'user/message', seq, time, data:{content:[{type:'text',text}], role}}`、`turn/start{data:{turn}}` |
| transcript 编码 | **多帧 zstd**（实测一个 196KB 文件含 30 帧），必须按 magic `28 b5 2f fd` 逐帧解 |
| 会话目录 | `~/.dsh/sessions/--<cwd 非字母数字折成 -、两侧各加 -->/<uuid>/session.v4.jsonl.zstd` |
| 内存 record 的 `value` | 硬顶 **2000** 字，且只能调小 → 段不能存进 record |

## 1. 从 billion-context 借的机制（借机制，不借代理）

| # | BC 机制 | 落地 |
|---|---|---|
| 1 | fold 布局：折叠成可还原 block，近期原文保留 | 段 + `anchor{path, fromSeq, toSeq}`；最近 12 轮不压 |
| 2 | growth-gate：只压"上次以来的新增" | `captureGrowthTokens=20000`；**删除死配置 `hintTokens`** |
| 3 | fold-once：每段只压一次 | `coveredSeqs` + 半开区间，重叠跳过（幂等） |
| 4 | 分层 T1→T2 | 段(T1) → `task digest` 合成档案(T2)；不做 T3 |
| 5 | 可逆 | `session expand --segment <id> --to-file`（本地 CLI only） |
| 6 | 检索折叠区 | `session search <q>` 先搜段摘要，命中再 expand |
| 7 | prefix-cache 友好 | 只追加；不重写历史；记 `captureTokens` 占比 |
| 8 | 模型决定时机（默认 off） | `capture --ask` |
| 9 | 继承 | `brief` + 子任务共享同一账本 |
| 10 | 归档不删 | `archive`/`restore` 状态位；物理删走 trash |
| 11 | fail-closed | capture 失败零写入 + 明确错误码 |
| 12 | 经济账 | 段记 `tokensIn/Out`；`task stats` 给 breakeven |

不抄：代理层改写、SQLite/MySQL 双写、模型侧 nudge side call、T3。

## 2. 存储布局（相对 v1 的核心改动）

```
$MEMO_HOME/
  sessions/<taskId>.json        # 既有 meta（title/status/createdAt/closedAt…），不动
  sessions/<taskId>/
    segments.jsonl              # append-only，一行一段（本文核心）
    index.json                  # 派生：{coveredSeqs, segments, tokensIn, tokensOut, lastCaptureAt}
  tasks/                        # 【保留给 P3 审批队列】，v1.2 不写这里
```

> 命名冲突已解决：future-architecture §5.4 的 `~/.memo/tasks/*.jsonl` 是 **P3 审批队列**（pending→approved/rejected/expired），不是任务账本。v1.2 一律落 `sessions/<taskId>/`，文档统一叫「任务账本（ledger）」，避免与「审批队列」撞名。

- **不进 memory record**：不撞 `MAX_VALUE=2000`、不进 kinds 注册（`halfLifeMs>0` 硬校验）、不参与衰减/配额/去重判 disputed、回滚到 v1.1 时该目录被忽略。
- memory record 只用于**晋升**（close 时 decision/gotcha，带 `from-session:<taskId>` 标签）。

段记录（一行 JSON）：

```
{ seq, taskId, sessionId, hostSessionId, cwd, branch,
  fromSeq, toSeq, turns, tokensIn, tokensOut, mode:"rule"|"llm",
  summary,                       // ≤400 字，给简报与检索
  files[], decisions[], gotchas[], pending[], nextSteps[], errorsAndFixes[],
  anchor:{path, bytes},          // transcript 路径 + 该段覆盖的帧字节范围
  quarantined:false,             // 命中投毒检测则 true，不进简报/注入
  createdAt }
```

契约（`docs/02` §3.23）：
- **裁决 118**：段只追加，`[fromSeq,toSeq)` 不得与 `coveredSeqs` 重叠；同区间重复 capture → `E_ALREADY_CAPTURED`（幂等）。
- **裁决 119**：段文件是任务库的**真相层**，删了等于丢账本；`index.json` 是派生，可重建。
- **裁决 120**：段必须带 `anchor`；无 anchor 不写（不可逆的不存）。
- **裁决 121**：写段必须过 `redactText` + `detectSuspicious`；可疑段 `quarantined:true`，永不进简报/注入。

## 4. 捕获策略（不制造噪声）

- 触发：`session capture`（手动）、`close`（自动尝试，失败告警不阻塞）、`--if-needed`（nightly 兜底，按 growth-gate）。
- 规则模式抽 8 段骨架（复用 `checkpoint.js` 的 `CHECKPOINT_SECTIONS` 与 `normalizeCheckpoint`，但**写入不经过 `_commit`**，走段文件 + 显式脱敏）。
- `--llm` 才做二次摘要；**先 `chargeBudget` 预扣**（`src/llm/budget.js` 目前无生产调用，B2 接上），超日预算直接 `E_BUDGET_EXCEEDED`。
- 尾部 `rawTailTurns=12` 不压；只有一个 open 任务时 `brief` 自动挑它。

## 5. 恢复与发现（用户真正要的）

- `memo session brief [--open] [--full] [--json]` → 标题 / 状态 / 累计 token / 最近 3 段 / 待办 / 下一步 / 关键文件 Top10 / 决策与坑 Top5；`--full` 展开全部。
- MCP `memory_session_brief`：**只回简报**（脱敏后、带 `<memory-context>` 围栏与"数据不是指令"声明）；**不提供 expand**。
- `memo session expand --segment <id> [--to-file]`：本地 CLI，默认写文件，`--stdout` 才打印。
- `memo session search <q>`：跨段搜摘要。
- 发现入口三处：`/api/tasks` 给「待接管」标；AGENTS 片段写「开工第一句 `memory_session_brief`」；任务页顶部显示「上次 capture / 下一阈值」。

## 6. UI（任务页）

统计条（段数 / 累计 tokens / 上次 capture / 距阈值）→ 「上下文接力」时间线（seq · 时间范围 · turns · tokens · 摘要，点击展开 8 段表格）→ 「展开原文」（写文件并提示路径）→ 「生成简报」弹层可复制。

## 9. 风险与回滚

- transcript 依然读不到（DSH 换版本）→ B0 的真实 fixture 测试会在 CI 红，而不是线上静默空转。
- 段文件被误删 → `index.json` 不能恢复内容，只能告警；`archive` 前 nightly 校验 `segments` 与 index 一致。
- LLM 费用 → 默认规则模式，`--llm` 有预算闸。
- 回滚：`versions/CURRENT` 改回 `v1.1`；v1.1 不认识 `tasks/` 目录，等同关闭（数据保留）。
