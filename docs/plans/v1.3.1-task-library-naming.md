## 问题量化

一个真实 session（`session-99680927`）里，用户说「在任务库里面创建任务」，agent 连续四次写错地方：

1. 建了 DSH 任务板卡（`task_board_*`），把「任务库」当成看板；
2. 切到 `dir:pushflow` 记忆分库，写了 8 条 `memory_write`；
3. 又建了 28 张任务板卡；
4. 直到用户说「就是临时记忆库」，才调用 `memory_session_start`，还先猜错 4 次参数名（`id`/`name`/`sessionId`）。

证据：

- MCP INSTRUCTIONS（`versions/v1.3/src/mcp/tools.js:12-31`）里「任务库」出现 **0 次**，只有「会话临时库」。
- `memory_write` schema 没有 `scope`（`tools.js:84-110`），传 `scope` 直接报 `E_INVALID_ARGS 未知参数: scope`。
- `memory_scope` 实际接受 `session:<id>`，但描述与错误文案只写 `repo:`/`dir:`（`core/scope-state.js:83-100`）。
- `memory_session_start` 必填 `title`，错误只说「缺少必填参数」，不说「参数名是 title」。

结论：不是模型笨，是**词表、入口、默认动作三处断点**。

## 设计

1. **词表**：MCP INSTRUCTIONS 固定「任务库 = 临时记忆库 = `session:<id>`；记忆分库 = `repo:`/`dir:`；任务看板 = `task_board_*` 只放状态」。
2. **入口**：`memory_session_start` 描述改「创建一个任务库（=临时记忆库）」，title 描述写明「参数名是 title，不是 id/name/sessionId」；返回 `任务库已创建: <scope>`。
3. **直达**：`memory_write` 增加可选 `scope`（只接受 `session:<id>`），一次性写入指定任务库且不切换当前分库；任务库不存在抛 `E_SESSION_NOT_FOUND`。
4. **纠错**：`memory_scope` 描述与错误文案补 `session:<id>`；参数校验错误列出可用参数。

## 为什么不是别的

- 不改 DSH 任务板：看板是执行状态，不是上下文；正确做法是让用户口语先映射到 `session:`。
- 不给 `memory_write` 开放 `repo:` scope：避免把「切库」和「写库」混成一个动作，长期分库仍走 `memory_scope`。
- 不做自动建库：用户说「写任务库」但没建时，fail-loud 提示 `memory_session_start`，不猜。
