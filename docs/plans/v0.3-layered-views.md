# v0.3 施工图：分层视图（L2 / L3 / 注入分级）

> 依据：[`docs/research/layered-memory-2026.md`](../research/layered-memory-2026.md)（分层怎么切、成本怎么控、注入怎么分级、收益怎么证）
> 目标版本：`0.3.0`（`versions/CURRENT` 仍指 `v0.2`，本版在 `versions/v0.2/` 内递增 —— 大版本才换目录）

## 1. 目标与非目标

| # | 目标 | issue |
|---|---|---|
| G1 | L2 场景块：确定性聚合，可整目录重建，零 LLM | #50 |
| G2 | 注入分级：Tier-0 目录 + 每层硬配额 + 证据链 | #51 |
| G3 | L3 画像：固定 LLM 预算、强制溯源、TTL 失效 | #52 |

**非目标**：向量检索（等 `noHitRate` 有痛感再说）、自动捕获 hook（跨端与成本问题未解）、重写 brief 语义。

## 2. 决策

- **D1 结构层不与 LLM 混**：L2 的"哪些记录聚在一起"由 `clusterNearDuplicates` + slot 分组决定，**零 LLM**；LLM 只可能出现在 L3 的表述里。
- **D2 视图是派生物，不是真相**：`$MEMO_HOME/views/` 整个目录删掉必须能重建出**字节相同**的结果；任何视图数据都不进 `items/*.jsonl`。
- **D3 配额是硬上限**：`brief.quota` 三层加起来 ≤1，代码里用「剩余预算递减」分配，不做归一化取整（否则小层永远分到 0）。
- **D4 L3 走既有裁决通道**：复用 `curateApply`，不新开写入路径；`sourceRefs` 为空即拒。
- **D5 预算进 policy，不写死**：`l3.maxCallsPerRun` / `l3.batchSize` / `l3.ttlMs` / `brief.tier0Chars` / `brief.totalChars` 全部配置化。

## 3. 冻结接口（实现须服从）

```js
// versions/v0.2/src/views/l2.js（A 路，新建）
export function viewDir(memoHome, scope);                      // <memoHome>/views/<scopeKey>/
export function buildL2(records, { scope, policy });            // → { blocks, builtAt, sourceCount, policyHash }
export function writeL2(memoHome, scope, built);                // 写 L2.jsonl + meta.json（原子：tmp+rename）
export function readL2(memoHome, scope);                        // → buildL2 的同形状；不存在返回 null
export function traceRecord(memoHome, scope, recordId, records);// → { blockId?, sourceRefs?, missing[], stale[] }

// versions/v0.2/src/render/tier0.js（C 路，新建）
export function renderTier0(records, { policy, limitChars });   // → { lines: string[], truncated: number, chars: number }

// versions/v0.2/src/render/brief.js（C 路，扩展，保持旧导出兼容）
export function renderBrief(records, { policy, now, blocks });  // blocks 可空 → 降级为扁平渲染
```

`blocks = null` 时 brief 必须**照旧工作**（降级路径要有测试）——视图是可选的加速层，不是依赖。

## 5. 测试与门禁

- 单测：稳定 blockId、单 record 单块、空库、块内排序、tier0 字符上限、配额截断、`sourceRefs` 为空即拒、TTL 过期不注入、trace 标失效
- 注入用例：**I21** 视图重建字节相同（含「删目录 → rebuild」双次）、**I22** 灌爆某层后 brief 仍守配额、**I23** L3 预算上限（假 judge 统计调用次数）
- 覆盖率：`views/` 与 `render/` 进覆盖率统计（**不许**像 `ui/` 那样排除——它们是纯函数，能测）
- 门禁不变：Q2 ≤900 行/文件、Q5 新导出登记、Q7 版本一致（0.3.0）

## 6. 风险与回滚

| 风险 | 对策 |
|---|---|
| 视图与真相层漂移（有人改了 record 没重建视图） | `meta.json` 存 `sourceCount + policyHash`；`brief` 发现 `sourceCount` 与当前不符时**用内存记录即时降级**并在 stderr 提示 rebuild |
| L2 聚类在无 slot 的 unstructured 记录上塌成一坨 | 复用 `dedupeScan` 的 `diceThreshold` 双路；块大小上限 `policy.views.maxBlockSize`（默认 64），超了按 createdAt 切片 |
| L3 生成跑偏（LLM 编内容） | 强制 `sourceRefs` + `memo view trace` 可逐条核；TTL 30 天；不进真相层的「事实」字段 |
| 配额让某层饿死 | `quota` 和 ≤1，按最小 1 行保底（`Math.max(1, floor(share*lines))`） |

**回滚**：删 `views/` 目录 + `policy.brief.quota=null` 即回到 v0.2.1 行为；没有任何真相层改动。
