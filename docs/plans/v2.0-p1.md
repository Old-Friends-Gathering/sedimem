### D4 基线 runner

- 输入：`pilot/p1a/config/local.json` 指定的本地授权 transcript（验证轨）或 corpus 内合成场景（评测轨）。
- 管线：capture 适配器（DSH transcript JSONL → 事件流，含 role/speaker/tool 状态/eventId/时间）→ 规范化+脱敏 → 按 token 窗口切段（tokenizer 按 ADR-101；无精确 tokenizer 时显式 estimated 并不出正式成绩）→ 抽取。

## 6. tokenizer ADR 预研结论（供 adr-101 决策）

| 候选 | 精确性 | 许可/分发 | 风险 |
|---|---|---|---|
| GLM 系列（zai） | 待查证：无公开精确 tokenizer 则不可用 | 未定 | 与生产模型一致但可能无精确实现 |
| DeepSeek-V3/R1 tokenizer | 公开精确（HF tokenizer.json） | MIT，可 vendor 数据文件 | 与实际生成模型（GLM）不一致，跨模型 token 差异需书面声明 |
| tiktoken 系列 | 精确但不含 GLM/DeepSeek | Apache-2 | 与目标模型不匹配 |

推荐：**首个正式效果实验目标组合 = DeepSeek tokenizer 计数 + 生成模型固定为实验声明中的模型**；若查证 zai 有公开精确 tokenizer 则优先 GLM 自身。附加约束：
1. 「查证 zai 是否有公开精确 tokenizer」是 adr-101 定稿的**前置任务**（产出查证记录），不是待定项；
2. ADR-101 必须明确所有 token 指标（切段窗口、预算、§7.2 的 20% 中位数降幅）的**计数口径归属**；
3. 若落定跨模型组合，效果实验结论须限定「仅在该 tokenizer 计数口径下成立，不外推到真实部署窗口」。
ADR 定稿前 pilot 切段一律标 estimated。
