## 问题

#223 已实现「MCP 工具调用挂车捕获」与「close 捕获」，但触发面仍有两个洞：

1. 只在调用 memory_* 工具时检查；agent 连续多轮不调 memory 工具时，30k 上下文不会落段。
2. `decideAutoCapture` 的 `interval-elapsed` 分支会在任意增长时按 `minIntervalMs` 捕获，既不是 30k，也会在长任务里产生过多小段。

目标：只要任务库 open 且有绑定会话，后台每 60s 检查一次转录增长；达到 `captureTokens`（默认 30k，按字节折算）才捕获，不依赖工具调用。

## 设计

- 新增 `scanOpenTasks(memoHome)`：读 `$MEMO_HOME/sessions/*.json` 登记文件，只取 `status: open` 且 `id` 合法的任务。
- 新增 `startAutoCaptureWatcher({ memoHome, intervalMs=60000, log })`：
  - 单例锁 `$MEMO_HOME/autocapture-watch.pid`：pid 存活则不再起第二个；
  - 每个 tick 对每个 open 任务调用 `maybeAutoCapture({ memoHome, taskId })`；
  - 只读 meta.json 绑定 `hostSessionId`；无绑定的任务跳过；
  - 所有异常吞掉并 log，绝不冒泡；
  - `unref()` 定时器，不阻止进程退出。
- `versions/v1.4/src/mcp/server.js` 启动时调用 watcher；多个 MCP server 进程由 pid 锁去重。
- `decideAutoCapture` 去掉 `interval-elapsed` 的「任意增长」触发，只保留：
  - `first-run`（首次有转录即捕一次基线）；
  - `threshold-reached`（growth ≥ captureTokens×bytesPerToken）；
  - `force`（close/手动）。
- 关闭：`session.ledger.autoCapture.enabled=false`，或删 pid 文件后不再起（下次 server 启动会重新起；要长期关必须改 policy）。

## 为什么不是别的

- 不放进插件 pre-step：插件在生产 bundle 里是快照，改它要重装；MCP server 每个 agent 都起，天然覆盖三端。
- 不用精确 token：每次解压 63MB zstd 才能拿 usage，违背零成本守卫；字节折算已在 #223 验证。
- 不做常驻 launchd：多一个安装步骤，且 MCP server 已覆盖活跃开发时段。
