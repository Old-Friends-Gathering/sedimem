## 2. 决策（先拍死，实现不得偏离）

- **D1 拆分只搬不改语义**：`MemoryService` 仍是唯一对外类，方法签名与返回形状不变；四个模块是「拿 service 当 this 的函数」，不是新类继承。
- **D2 kind 的唯一真相在 `policy.json`**：`record.js` 不再持有清单；`createRecord(input, deps)` 的 `deps.kinds` 缺省回落 `defaultPolicy.kinds`。未登记 kind → `E_INVALID_RECORD`。
- **D3 JudgePort 默认无 LLM**：`ruleJudge` 是确定性规则（strong+同 slot 比 hits，其余 keep_both）。自定义 judge 通过 `createMemoryService({ judge })` 注入。
- **D4 compact 是唯一物理删除入口**：只有「墓碑 + `purge` 标签 + 超过 grace」会被删；普通墓碑保留（as-of 仍可回查）。压实前自动备份 `.bak.<ts>`，只留最近一份。events 永不删。
- **D5 检索指标不存 query 原文**：事件只存 `qHash`（sha256 前 12 位）、`hits`、`topScore`、`staleHits`。分母为 0 时指标写 `null`。
- **D6 所有新能力走既有扩展点**：judge 走构造注入，kind 走 policy，compact 走 service 方法 + 新 CLI 子命令；不新增环境变量开关。

## 4. 冻结接口（实现前定，实现只许遵守）


## 7. 风险

| 风险 | 处置 |
|---|---|
| 拆分类导致 MCP/CLI 行为漂移 | A 的验收含「prototype 方法集合不变」断言 + eval 全跑 |
| kind 数据化改动影响衰减/排序 | B 必须给出迁移前后同输入的排序一致性单测 |
| curateAuto 误合并真实不同事实 | 默认 judge 保守（weak 一律 keep_both）；merge 非破坏，可回查 |
| compact 误删 | 三重条件 + `--dry-run` + 自动备份；I19 断言「未超期不删」 |
| 指标写入拖慢检索 | search 事件走既有批量 flush 通道，不 fsync 每条 |
| 两车道同时改 maintenance.js | 按 §3 的分段约定，且 Lead 合并时统一 review diff |
