## 3. 前置缺陷（必须先修，否则 UI 数字是错的）

`versions/v0.1/src/cli/nightly.js:204` 写 `metrics/<date>.json`，**没有 scope**：

```js
const file = path.join(metricsDir, `${plan.date}.json`);   // 多分库同日互相覆盖
```

后果：`/api/timeline` 与卫生页趋势只能看到一个分库，且数据丢失是静默的。
修法：写 `metrics/<date>.<scope 归一化>.json`（`:`→`-`），读路径先找新名、回退旧名。

## 6. 冻结的接口形状（并行开发的唯一依据）

```js
// service（W1）
await svc.events({ since, until, ops, limit = 200 })      // → { events: [{ts,op,scope,id,detail}], scanned, truncated }
await svc.exportRecords({ since, until, status = 'active', kind, limit = 2000 })
                                                            // → { records: [record], total, limited }

// HTTP（W3，全部 GET，JSON）
/api/summary                                        → { ok, scope, memoHome, version, policy, stats }
/api/brief?lines=80                                 → { ok, text, generatedAt }
/api/today?date=YYYY-MM-DD&tzOffset=480             → { ok, date, counts, timeline }
/api/records?status=&kind=&since=&limit=&q=         → { ok, records, total, limited }
/api/graph?limit=300&days=90                        → { ok, nodes, edges, sampled }
/api/hygiene                                        → { ok, candidates, merged, superseded, suspicious, series, doctor }
/api/timeline?days=30&tzOffset=480                  → { ok, series }
错误                                                → { ok:false, code, message } + 400/500
```

`/api/graph` 的节点/边形状（W3 产出、W5 消费）：

```js
node = { id, label, kind, status, subject, createdAt, hits, degree }
edge = { from, to, type: 'same-entity'|'supersedes'|'duplicate-of'|'disputed-with', weight }
```

## 9. 风险登记

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 力导向在 300 节点下掉帧 | 中 | 交互卡 | O(n²) 45k 对/帧可接受；`alpha` 衰减停帧；不达标则降到 200 节点并显式提示 |
| 时区切日错位（`tzOffset` 处理错） | 中 | 「今日」页数字错 | I14 用 `tzOffset=0` 与 `480` 双跑；只用 `[from,to)` 半开区间 |
| 记录正文注入 HTML（XSS = 投毒面） | 低 | 脚本执行 | 全部 `textContent`；CSP `script-src 'self'`；S9 无外链 |
| suspicious 原文泄漏到 UI | 低 | 投毒内容被当真 | 服务端遮蔽（裁决 16 复用），I13 断言字符串为 `[suspicious withheld]` |
| metrics 改名破坏旧数据读取 | 中 | 趋势图缺历史 | 读路径先新名后旧名，单测覆盖两种文件名 |
| 端口被占用时静默换端口 | 低 | 用户找不到页面 | 报错并提示 `--port`，不递增 |
| UI 与 CLI 语义漂移（label 在两端各拼一次） | 中 | 显示不一致 | label 只由服务端生成（08 §4.2 约定） |

## 10. 回滚方案

- **UI 层**：`ui/` 是独立静态目录，出问题可直接不加载（`memo serve --no-ui` 只提供 API）。
- **服务层**：`serve` 是新增子命令，不影响 CLI/MCP 任何现有路径；删掉子命令即回到 v0.1.2 行为。
- **metrics**：新旧文件名并存读取；若要回退，把新文件改回旧名即可（写入端单点）。
- **数据面**：`events()`/`exportRecords()` 为纯读，无写入路径改动，回滚零数据风险。
