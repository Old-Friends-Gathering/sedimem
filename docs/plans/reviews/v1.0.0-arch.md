## 逐题回答（对任务 1–5）

1. **W1 能否拆**：能。5 条环 = 4×(service↔path) + policy 自 import，根因是错误工厂反向引用（A1）；2 条反向依赖（web→mcp 常量、mcp→cli 常量）下沉常量即可。但「path 模块导出纯函数」与现状（收 svc 实例）不符（A2），模块图漏 session/capture（A3）。
2. **波次顺序**：W3 依赖 W1 成立；主要风险是 C1 的 llm 调用方矛盾与 C2 的 W1/W5 双改 mcp 门禁抖动，无根本性顺序倒置。
3. **derived 兼容**：schema 层兼容（未知键通过校验），但与 append-only/asOf/supersede/I44 的交互计划未交代（B1/B3），落盘位置是硬矛盾。
4. **异步派生**：CLI 单次进程必丢，计划只有 `--retry` 无队列持久化，缺口 = outbox/同步降级二选一（B2）。
5. **门禁冲突**：Q12 编号撞车（C3）、Q5 需补登记（C4）、Q2 400 行收紧会扫到 W5 清单外文件（C4）；Q13 与「不用 CDN」自洽。

## 判定

**不通过（需修订后复审）**：B1、B2 两项阻断必须先在计划中补设计；A1–A3、C1 建议随 v3 一并修订。
