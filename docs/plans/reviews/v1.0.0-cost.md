# v1.0.0 计划（v2）成本与隐私审核

> 审核人：成本与隐私（agent-32）。对象：`docs/plans/v1.0.0-refactor.md`（v2）§1.3 / §2 / §6 / §8。
> 单价依据：计划 §1.3 自述 GLM-5.3-Flash ¥0.8/M in、¥2.8/M out、缓存命中 ¥0.23/M（未另行验证，标「判断」处见正文）。

## 1. 成本重算（按题设参数，非计划自述区间）

| 调用点 | 假设 | 单次成本 | 日频 | 日成本 | 月成本（30d） |
|---|---|---|---|---|---|
| D1 写入派生 | 2k in / 200 out | 0.8×2000/1M + 2.8×200/1M = **¥0.00216** | 1000 | ¥2.16 | ¥64.8 |
| D3 checkpoint | 20k in / 1k out | 0.8×20k/1M + 2.8×1k/1M = **¥0.0188** | 20 | ¥0.376 | ¥11.3 |
| D4 brief | 1k in / 150 out | **¥0.00122** | 1 | ¥0.001 | ¥0.04 |
| D2 裁决 | 1–3k in / 30 out（计划 §1.3②） | ~¥0.001–0.003 | 低频（估 20/日） | ~¥0.04 | ~¥1.2 |
| **合计（基线）** | | | | **≈ ¥2.6/日** | **≈ ¥77/月** |

**结论：无量级错误，但方向是高估。**
- 计划 §1.3 称 D1 单次 ¥0.004–0.007，而按其自述 0.8–2k in / 100–200 out 上限算只有 ¥0.00216 —— 单次高估 2–3×；「常态 ¥10/日（1000 写入）」（`v1.0.0-refactor.md:49`）对基线 ¥2.16/日是 4.6× 裕量，作预算上界成立，作预估则失真。
- **漏项（会把 ¥2.6 推向 ¥5–8/日）**：
  1. **重试**：§2.1 重试 1 次 → 最坏 ×2（¥4.3+/日）。
  2. **schema/system prompt 重传**：`complete({system, jsonSchema,…})`（`v1.0.0-refactor.md:72`）每次调用都要传 schema 与 system prompt；自有 sha256 缓存 key 含 promptVersion，但 **schema 变更不入 key**（§2.1 只写 `model+promptVersion+input`，:79）——schema 随 promptVersion 走才能省；若 provider 端无 prompt-cache，每条写入额外 1–2k in（+¥1–2/日）。
  3. **缓存未命中**：自有 sha256 缓存只对「完全相同输入」命中，D1 每条原文唯一 → **D1 缓存命中率≈0**，§1.3「缓存命中再省约 60% 输入费」对 D1 基本不成立（只对 D4 日频重跑、D2 重复簇有意义）。判断/未验证：假设 provider 侧无自动 prompt cache。
  4. 多轮 tool 调用：本设计单轮 complete，无此项 —— 不漏。

## 2. 护栏逐条可绕过性（§2.1，`v1.0.0-refactor.md:79`）

| 护栏 | 判定 | 依据与绕过方式 |
|---|---|---|
| ¥15/日滑动窗口 | **会被绕过（严重）** | `budgetStatus()`（:74）是进程内状态。memo CLI 每次调用是独立进程，MCP server 是常驻进程 —— **两边各算各的**，且 CLI 进程退出即丢计数。必须落盘共享台账（如 `$MEMO_HOME/llm-budget.jsonl` 追加 + 启动重放），计划未写。 |
| 单次 4k in / 300 out | **与 D3 自相矛盾（阻断）** | §1.4 要求 D3 输入 ≤20k（上限 50k）（`v1.0.0-refactor.md:54`），§2.3 D3 输入「新增对话+上一版 checkpoint」（:96）。4k 上限若全局生效 D3 直接不可用；若按调用点豁免必须写明豁免表，否则实现各取一头。 |
| 8s 超时 / 重试 1 次 | 基本够用 | 异步派生不阻塞写入（:78/:94）；但重试计入预算的口径未写（见 §4）。 |
| sha256 缓存 | key 设计正确（含 model+promptVersion），两处缺口 | ①schema 未入 key（见上）；②并发写同一输入：异步派生并发发起时双双 miss、重复付费——需 per-key in-flight 去重或落盘缓存。缓存若只在 MCP 进程内存，CLI 永不命中。 |
| 批 ≤10 | 形同虚设 | D1 是每条写入一次、D2 簇天然 2–10、D3/D4 单次 —— 现有四个调用点根本没有 >10 的批量入口，该护栏无对象；真正要防的是 `--retry` 批量回补（见 §4）。 |

## 3. 隐私

- **redact 覆盖面（依据 `versions/v0.6/src/api/write-path.js:23-45,86-88`）**：入库时 redactInput 依次处理 text、value、title、source.quote 四个字段，**写入门禁保证原文不落盘**（:84 注释）。SPO 的 subject/predicate 不脱敏（只脱 value）——语义字段泄漏弱，可接受但应写明。**summary 是派生字段**，从已脱敏 text 生成，天然继承。→ 四个面基本覆盖。**但注意：redact 类别只有密钥/令牌/内网 IP（`hygiene/redact.js:6-14`），不含人名/邮箱/手机号等 PII** —— 「隐私」实际保护范围 = 凭据级，计划 §8 称「隐私外泄」风险已处理（:171）表述过强，应降格为「凭据级脱敏」。
- **D3 是裸 transcript 入口（严重）**：§2.4 读 `~/.dsh/sessions/**` 原文（:103）——这些文件从未经过本库 redact 管道，若 `egress='allowed'`，checkpoint 压缩会把**未脱敏对话**整段送出网。D3 输入必须先过 redactText，计划未写。
- **local-only 漏洞路径**：
  1. `local-only → provider:'none'`（:81）逻辑自洽；env 无 `MEMO_LLM_API_KEY` 时 `ready:false` 走规则兜底（:77-78），均 fail-safe。但 **D4 nightly 若由 launchd/cron 跑，加载的是 launchd 环境**：有 key 且 policy 未设 local-only 时，夜间无人值守出网只靠凭据级 redact —— 建议 nightly 任务默认强制 local-only 或需显式 opt-in。
  2. `policy.redact.enabled=false`（`write-path.js:25`）在 v0.6 已存在：一旦用户关掉 redact，所有派生字段出网内容即全裸。计划应规定 `egress='allowed'` 时禁止 `redact.enabled=false`，二者互斥未声明。
  3. MCP server 与 CLI 读同一 policy 文件，无分叉路径（`mcp/server.js:681-689` env/cwd 解析一致）——判断：无额外绕过。

## 4. 失败语义（deriveStatus='failed' 存量回补）

- `memo derive --retry`（`v1.0.0-refactor.md:94`）**未写成本上限**：若某日 provider 全挂、1000 条全 failed，次日一次 `--retry` 批量回补 = 单进程内 1000 次调用 ≈ ¥2.2（基线）—— 不会打爆 ¥15 预算的「金额」，但若叠加 D3 大输入或重试放大，且预算台账不跨进程共享（§2 第一条），retry 进程**根本不知道当天已花多少**。要求：①`--retry` 复用同一落盘预算台账并受 ¥15 约束；②给 `--retry` 加单次运行调用上限（如 `--max N`）与断点续跑（按 deriveStatus 挑选，天然幂等）。
- fail-open 本身语义清晰（:78 写入必成功），无异议。

## 5. 订阅 vs API（与 DSH 自身调用重复计费）

- 事实：DSH 的会话压缩/总结走用户已有 zai-coding 订阅；sedimem LlmPort 用独立 API key（§2.1），**是另一笔钱**。D3 若对 DSH transcript 再做一次 20k-token 总结，与 DSH compaction 产出**语义重复、双重付费**。
- 计划已部分自救：§2.4「DSH 优先 compaction/summary 事件」（:103）—— 该事件是订阅已付产物，复用它成本为 0，**应升格为硬规则：凡 transcript 带 DSH compaction 事件，禁止再调 LLM 重总结**，只在无事件时才走 D3 的 LLM 路径（Codex/Claude 或事件缺失）。
- **判断**：D1/D2/D4 保留 API key（低值高频、需在 CLI/MCP 离线触发，订阅不可编程调用）；D3 以「先吃订阅产物、API 仅兜底」为原则。¥77/月的 API 账单应写进 README 成本披露。
