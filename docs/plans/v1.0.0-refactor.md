## 0. 本版要达成的三件事

1. **可维护**：把「文档声明的分层」和「代码实际的分层」对齐，拆掉 5 条循环依赖与 2 条反向依赖。
2. **更简单**：功能面**只减不增**；把 2222 行自研图谱换成成熟库，删掉自己维护的那部分。
3. **文档不再漂移**：文档分类（契约/手册/历史）+ 头部元信息 + 发版四件套 + **Q14 机械门禁**，让「忘了更新文档」直接红 CI。

**明确不是本版目标**：新能力（LLM、云同步、导入器、编辑入口、3D 图谱）。那些留在 1.1+，且必须先有计划文档。

## 1. 调研结论（决定本版取舍）

### 1.1 记忆机制（ICLR 调研）

- **ICLR 2027 截至 2026-11-14 未放榜**（评审中，1–4 分制；无官方 oral/award 名单）——不编造「满分论文」，回退到已公开的高分/口头报告论文。
- **TriMem（NeurIPS 2026）**：主张「原始对话指针 + 实体档案 + 抽取事实」**三粒度并存**，并指出纯原子事实「丢细节、伤深层推理」→ **正面验证我们 append-only 真相层不可省**，且提示「实体档案」是一种值得做的派生索引形态。
- **MemAgent（ICLR 2026 Oral）**：固定大小记忆区 + 每段**有损覆写**，线性复杂度、32K 训练外推 3.5M（<5% 损失）。→ **反面教材**：有损覆写与 append-only 哲学相斥（不可回溯、不可审计）；只借「恒定大小的 rolling summary 通道」这一个想法，且本版不做。
- **MemoryArena（ICML 2026）**：多会话**相互依赖**任务上的 agent 记忆 benchmark → 提示我们的 eval 应补「跨会话依赖」类用例（本版只登记，不新增用例）。

**结论**：架构方向（真相层 + 派生层 + Agent 裁决）经三篇论文交叉验证**不需要改**；1.0.0 不动记忆语义，只做工程收口。

### 1.2 图谱可视化

- 主方案 **`force-graph@1.52.0`（2D，MIT，UMD 单文件 173,081 B / gzip 56,470 B，2026-09-28 发布）**：与 `3d-force-graph` 同作者同 API，canvas 2D 文字清晰（解决「标签糊」），UMD 直接落 `ui/vendor/`，零构建、禁 CDN。
- **放弃 3D**：`3d-force-graph` 自带 three（1.39MB / gzip 365KB），第 3 维只贡献雾化装饰不贡献信息密度；现有「拖拽旋转」交互可在 2D 用平移/缩放替代。
- 备选（不选）：`d3-force-3d` 只换布局（9KB）——只解决「布局一般」，标签糊与 840 行维护成本都留着。
- 结论：**删掉 `ui/graph.js`(599) + `ui/layout.js`(241) 自研实现，改用 force-graph**，预计 UI 层净减约 700 行。

### 1.3 文档漂移（现状，必须修）

高严重度：`README`（288 个测试→实测 471、I1–I24→I1–I40、配置链接指 v0.3）、`docs/06`（操作路径全指 v0.3，同一篇里三种版本路径并存）、`docs/07`（头部门禁数字 8/8/3 与正文 11/9/3 自相矛盾、`cd versions/v0.3`）。
中：`docs/01`（架构图缺 v0.3 `views/`、v0.4 `capture/`、v0.6 `session/`）、`docs/03` §2（端口表把已落地的 hybrid/vector/embedder 写成「未来」）、`docs/08`（头部自称 v0.2 契约却夹 v0.4 增补）。

根因三条：① 权威文档靠正文追加「裁决 N」续命，头部定位语从不改；② 运维路径硬编码 `versions/vX.Y`；③ 数字散落多文件手工同步，Q10 只管版本号三处一致。

### 1.4 代码基线

- `versions/v0.6/src` **12598 行 / 60 文件**；`tests` 100 文件 / 11207 行；`ui` 11 文件 / 2222 行；导出 204 个。

## 3. 目标模块图（11 模块，依赖只向下）

```
入口：cli / mcp / web(static)
            └── service（唯一对外门面，纯编排）
     ┌───────┼────────┬─────────┬──────────┐
  hygiene  storage  index   render/views（派生层）
     └───────┴────────┴─────────┴──────────┘
  core（scope / time / text / hash / ids / record —— 单一实现）
  config（policy 单一来源，去掉自 import）
```

硬规则（变成可执行断言，见 §6）：
- 入口层只做「参数 → 调用 service → 输出」，**不得 import storage 具体实现**，不得互相 import。
- `service` 单向 import 各 path 模块；path 模块**只导出纯函数**（接收 service 作为参数），不得反向 import service。
- `core/*` 是唯一实现 scope/时间/文本归一的地方；其它模块 import 它，不重复写。

## 5. 文档治理（本版核心交付之一）

### 5.1 三分类

| 类 | 文档 | 纪律 |
|---|---|---|
| **契约**（现状，必须同步） | README、01、02、07、08、`docs/index.html` | 改代码的 PR 必须同 PR 更新；不一致时**以文档为准**并开门禁 issue |
| **手册**（现状） | 06 | 路径一律写 `versions/$(cat versions/CURRENT)`，禁止硬编码 `versions/vX.Y` |
| **历史**（冻结） | 00、04、05 §5、09、10、plans/v0.2–v0.7 | 只追加不改写；头部 `doc-kind: history` + `as-of: vX.Y`

### 5.2 头部元信息（现状型必带）

```markdown
<!-- doc-kind: contract
     doc-version: 1.0.0
     verified-at: 2026-11-14
     verified-against: versions/CURRENT
-->
```

### 5.3 发版四件套（每个 X.Y.Z 合并前逐项打勾，写进 `docs/05` §6.3）

1. `versions/<v>/CHANGELOG.md` 最新段 == `package.json` version（现有 Q7）。
2. README 版本表 + 快速开始的**测试数 / eval 区间**刷新为实测值。
3. 06/07/08 中所有 `versions/vX.Y` 路径与门禁数字刷新到新目录。
4. `docs/index.html` 时间线加本版（现有 Q10）。

### 5.4 Q14 门禁（新建 `tools/docs-drift-check.mjs`，进 `quality` job）

可机械判定的 5 条：
1. 现状型文档缺 `doc-kind/doc-version/verified-at` → fail。
2. `doc-version` ≠ 当前版本（由 `versions/CURRENT` + CHANGELOG 最新段推导）→ fail。
3. 现状型文档出现 `versions/v\d+\.\d` 且 ≠ CURRENT → fail（history 与 `plans/` 豁免）。
4. README 的「N 个测试」「I1–M」正则抓取：M 必须等于 `eval/cases/` 文件数；N 必须等于 `quality` job 读到的实测测试数（脚本接受 `--tests N`，CI 从上一 job 产物读）→ 不一致 fail。
5. `docs/07` 头部命令块的门禁项数必须与该节标题数一致（消除 8/8/3 vs 11/9/3 这类自相矛盾）。

豁免机制：脚本内 `ALLOWLIST = [{file, pattern, reason, until}]`，`until` 过期自动重新报红。

## 6. 质量与评测策略

- **架构即断言**：新增 `tests/unit/arch-boundaries.test.js`——静态扫描 `src/` 的 import 图，断言「无 web→mcp、无 mcp→cli、无 cli→storage、无 api↔api 循环」。
- **行为不变**：每次迁移前后 `node eval/run.js` 分数必须完全相同（I1–I40 现状）；`471 tests` 全绿是合并条件。
- **测试瘦身**：11207 行测试里按「是否还能抓住一个真实回归」审计一遍；目标 ≤9000 行但**不减断言覆盖**（合并重复 fixture，不删用例）。
- **门禁清单 1.0.0**：Q1–Q14 + S1–S9 + 覆盖率（lines ≥85 / branches ≥70 / functions ≥90）。

## 9. 明确不做（1.0.0 边界）

1. 不引入 LLM（`provider=none` 行为不变）。
2. 不做导入器、人类编辑入口、Web 写端点（留在 1.1+）。
3. 不做云同步/多机（1.0 仍是本机）。
4. 不换 SQLite 之外的后端；不引入打包器/CDN。
5. 不新增记忆语义（去重/裁决/失效规则冻结在 v0.6 行为）。
