## 1. 关键结论（有据可查）

### 1.1 CLM（arXiv:2609.37725，2026-09-29，UW + Meta）

把 live context **全文镜像成文件**，模型用**任意 Bash** 改写；无 write 工具、无 diff、**无校验无回滚**。ContextBench 四任务（Needle/Sudoku/KV/Log Triage）；零样本 BrowseComp-Plus **+11.4%**、prefix-reuse FLOPs **−21.5%**；EdgeBench-10 44.6 vs 42.3、179 vs 437 PFLOPs；RL 28.8→42.5%；**负结果：训练前 9B 小模型直接可编辑不如 summary 基线**。

**对我们的三条**：① 结构映射 = 让 Agent 改**可重建派生视图**，真相层 append-only 正好补上它缺的回滚；② 真实成本是 **re-prefill**（缓存失效），不是 API 账单，别照搬 FLOPs；③ 它自认 prompt-injection 可经编辑持久化 → 派生视图必须**每次从真相层重建**、不接受持久注入。

### 1.2 记忆机制（ICLR 2027 未放榜 → 三篇替代）

TriMem（NeurIPS 2026）三粒度并存 → **正面验证 append-only 原文层不可省**；MemAgent（ICLR 2026 Oral）有损覆写 → 反面教材；MemoryArena（ICML 2026）→ eval 补跨会话依赖。**架构不动。**

### 1.3 LLM 工序（8 家对照）

- Mem0 v3 放弃「ADD/UPDATE/DELETE/NOOP 四选一」→ **裁决归规则层，LLM 只做抽取**（`mem0/configs/prompts.py:176-220` 仍在但默认不用）。
- LangMem 区分 hot path / background → 抽取放后台。
- Graphiti 抽取与消歧分开（`extract_nodes` / `dedupe_nodes`）→ 与我们 `dedupe_scan → curate` 同构。
- Letta sleep-time compute 离线巩固（arXiv 2504.13171）。
- TriMem 用 TextGrad 迭代 prompt → 我们只做**离线**失败样本→prompt 迭代。

## 2. LLM 层（按审核重写）

### 2.1 LlmPort

```js
// src/llm/port.js —— 零依赖；openai-compatible 协议
createLlm({ policy, env, fetchImpl, clock }) → {
  ready, provider: 'openai-compatible'|'none', model,
  complete({ purpose, system, user, jsonSchema, maxInputTokens, maxOutputTokens, timeoutMs }),
  budget() → { spentCnyToday, limitCny, calls, blocked }
}
```

- **provider**：`openai-compatible`（`MEMO_LLM_BASE_URL` / `MEMO_LLM_API_KEY` / `MEMO_LLM_MODEL=glm-5.3-flash`）；`none` → `ready:false`，派生走规则兜底并标 `deriveStatus:'no-provider'`。
- **按用途分档**（审核 C1 修复；全局上限不存在）：

| purpose | maxInput | maxOutput | 说明 |
|---|---|---|---|
| `derive` | 4k | 300 | 单条记忆派生 |
| `curate` | 8k | 300 | 同簇裁决（≤10 条） |
| `checkpoint` | 24k（硬 32k） | 1500 | 会话 8 段 |
| `brief` | 2k | 400 | 日频主题句 |

- **预算与缓存必须落盘跨进程共享**（审核 C2 修复）：`$MEMO_HOME/llm/budget.json`（含 `{date, spentCny, calls, byPurpose}`）+ `$MEMO_HOME/llm/cache.jsonl`（键 `sha256(model|promptVersion|purpose|input)`），读写都在文件锁内；CLI / MCP 常驻 / launchd nightly 共用同一份。超预算 → 全 purpose `blocked`，derive 落 `budget-exceeded`。
- **失败语义**：超时 8s、重试 1 次（指数退避 2s）、JSON/schema 校验失败即视为失败；**写入永不因 LLM 失败而拒绝**，标 `deriveStatus ∈ ok|failed|no-provider|budget-exceeded|privacy-blocked`。
- **隐私**（审核严重项修复）：出网前对 `text / value / title / summary / source.quote` 全部走 v0.4 `redact`；`policy.llm.egress ∈ local-only|allowed`；`local-only` 强制 `provider:none`；**`egress=allowed` 且 `redact.enabled=false` 时启动抛 `E_LLM_PRIVACY_CONFLICT`**（互斥显式化）；D3 的 transcript **必须**先 redact 再出网。
- **订阅 vs API**（审核建议）：DSH 内优先复用 `compaction/summary` 事件（零额外 token、走用户订阅）；API key 仅用于 Codex/Claude 路径与 D1/D4；两者计费分开，`memo llm status` 只报 API 侧。

### 2.2 派生数据存哪（审核 B1/B3 修复）

- **独立 sidecar**：`$MEMO_HOME/derived/<scopeKey>.jsonl`，每行一条派生事件：
  `{id, validFrom, promptVersion, model, title, summary, tags, spoSuggestion?, kindHint?, deriveStatus, ts}`
- **真相层 `items/<scope>.jsonl` 一字节不动** → I44 就是「derive 前后 items 文件 sha256 相同」。
- 生效规则：某记录取 `(id, validFrom)` 最新一行为准；缺失或 `deriveStatus!=='ok'` → 读端回落规则字段（title=subject·predicate / text 前 N 字）。
- **不 bump 版本链**：派生不写 `withPatch`，不产生新 record 版本，`asOf` 回查只受真相层影响。
- 读端：`service.refreshView()` 已存在（裁决 39），改为同时加载 sidecar 增量；sidecar 可删可重建（`memo derive --rebuild`）。
- **supersede 后**：新 `(id, validFrom)` 无 derived → 自动入队；旧 deriv​ed 保留作历史（不参与当前读）。

### 2.3 异步派生队列（审核 B1/B2 修复）

- **同步入队**：`write()` 在 scope 锁内追加一条 outbox 行到 `$MEMO_HOME/derive-queue/<scopeKey>.jsonl`（`{id, validFrom, enqueuedAt, attempts}`），**只做 append，不做 LLM**。
- **三个 drain 者**：
  1. `memo derive --drain [--limit N]`（显式；`memo write --derive now` 等价于写后立刻 drain 1 条）；
  2. MCP 常驻进程：空闲 30s 定时 drain（每次 ≤5 条，受预算约束）；
  3. `nightly`：兜底 drain 全量（≤200 条）。
- **幂等**：`(id, validFrom, promptVersion)` 已有 `ok` 派生则跳过；`attempts ≥3` 的行标记 `dead` 并写事件 `derive_dead`（不阻塞队列）。
- **锁**：drain 先在队列锁内「抢占并标记 in-flight」，再出锁调 LLM，成功后在 sidecar 锁内 append。

### 2.4 四个调用点（含 schema 修正）

| 点 | 触发 | 输出（**只进 derived**） | 失败 |
|---|---|---|---|
| **D1 派生** | drain 队列 | `{title≤40, summary≤80, tags≤5, spoSuggestion?, kindHint?}` —— **不含 `kind`/`text`/`value`**（审核 B2 修复：`kindHint` 只作审计，`kindHint!==kind` 时记 `kindMismatch:true`） | `deriveStatus` + 规则兜底；重试 ≤3 |
| **D2 裁决** | `curate --judge llm` 显式 | `{decision:'a_wins'|'b_wins'|'merge'|'keep_both', note≤60}` | 回落 `ruleJudge` |
| **D3 checkpoint** | `memo session checkpoint [--auto] --llm` | 8 段 JSON（≤8000 字） | 不写脏数据，保留上一版，报 `E_LLM_UNAVAILABLE` |
| **D4 brief 主题句** | nightly，缓存日频 | 3–5 句（≤400 字）进 brief `## 今天在做什么` | 跳过该段 |

- **D2 默认关**（审核 B4 修复）：`policy.llm.judge='rules'` 默认；`'llm'` 必须显式配置并通过 `createMemoryService({judge})` 注入，**不读环境变量**（裁决 50）。

### 2.5 门禁与不变量

- **Q15 派生层不可写真相层**：单测「恶意/超长/伪造 truth 字段的 LLM 输出经 `applyDerivation` 后，`items/*.jsonl` sha256 不变」；且 `src/llm/**` 不得 import `storage/**`（arch 断言）。
- **I44**：派生前后真相层 sha256 相同（同一条记录）。
- **title 纪律不被废**（审核修正）：`derived.title` **只在调用方未给 title 时兜底**；`policy.write.titleEnforce` 仍默认 false，v1.1 起才硬拒；`derived.title` 不豁免 `E_TITLE_MISSING`。

4. `llm/` 只被 `service` 与 `render` 顶层调用；**不得 import storage/index**（落盘由 service 做）。

### 12.4 可编辑的安全设计（最容易做错的部分）

- **默认仍只读**：`memo serve` 默认 `--readonly`；开写需 `--write` **且** `MEMO_WRITE_TOKEN`（首次生成写 `~/.memo/serve-token`，0600）。
- **仅 loopback** + `Origin` 校验（防 DNS rebinding）；写请求一律 `Authorization: Bearer <token>`。
- **编辑 = 追加新版本，永不原地改**：`POST /api/records` 走 `supersede(旧, 新)`，真相层只增不改；UI 上「保存」= 「提交新版本」。
- **乐观并发**：请求带 `ifMatch:{id, validFrom}`，与当前 active 版本不符 → **409**，前端提示「有人先改了，刷新看差异」。
- **审计**：每次写追加 `events.jsonl` `op:'ui_edit'`，含 `before/after` 的 `id+version` 与 `source.agent='ui:local'`。
- 派生自动刷新：写入后入 `derive-queue`（§2.3），页面下次加载即看到新 title/summary。

### 12.5 五个导入器（全部 dry-run 优先）

`memo import <source> <path> [--dry-run|--apply]`，默认 dry-run；`--apply` 写 `import` 事件并记源文件 sha256（重跑幂等）。

| 源 | 解析 | 映射要点 | 坑 |
|---|---|---|---|
| `agents-md` | `AGENTS.md` / `CLAUDE.md` 标题层级 | 二级标题 → `subject`，正文首句 → `value`，`kind=decision` | 标题层级不稳，空节跳过 |
| `basic-memory` | Markdown + frontmatter（`- [category] observation`） | 一行一 observation → 一条记录 | 分类名不是我们的 kind，要映射表 |
| `obsidian` | `*.md` + `[[wiki-link]]` | 每个 `##` 小节一条；`[[x]]` 记进 tags | 链接解析不做全文，只记 tag |
| `mem0` | `memories.json`（`{id,memory,metadata}`） | `memory` → `value`；`metadata.category` → `kindHint` | 无 SPO，全是 unstructured |
| `cline-memory-bank` | 六文件（projectbrief 等） | 每文件 → 一条 `decision`（标题=文件名） | 内容极长，需 `long-form` + 拆分建议 |

### 12.7 会话库进 UI 的三条硬约束

1. **只读优先**：`#/session` 首版只显示 + 提供 checkpoint/close 按钮（走既有 CLI 语义），不提供"编辑 state 正文"（避免手改污染 nextSteps）。
