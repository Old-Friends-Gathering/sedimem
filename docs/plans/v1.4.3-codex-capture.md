# v1.4.3 Codex 会话捕获

状态：执行中（2026-11-18）
依据：用户 m06088/m06124/m06143 —— 跨 harness（Codex）会话也要录入任务账本，自动捕获一起做。
版本规则：P0b 之后的小版本；本计划只改 v1.4，不改历史版本目录。

## 问题量化

- `versions/v1.4/src/session/transcript.js` 已有 `readCodexRollout()`，但 `captureTask()` 只读 DSH 转录，`source.kind` 固定 `dsh`；`readCodexRollout` 在 `src/cli`、`src/session` 之外零引用。
- Codex 环境没有 `DSH_SESSION_ID`，自动捕获无法解析当前会话；任务账本只有 DSH 段。
- 结果：Codex 会话只能通过 MCP `memory_write` 写事实，不能形成 llm/rules 段，多会话交接缺一块。

## 设计

1. **统一 source 适配**：`captureTask({ sourceKind })` 支持 `dsh` / `codex`；Codex 走 `readCodexSession()`（`readCodexRollout` + `toTurns`），段 `source.kind='codex'`，`source.events` 记录原始记录数。
2. **按 id 解析**：`findCodexRolloutById()` 在 `~/.codex/sessions/**` 按文件名里的 session id 找 rollout；`resolveSessionSource()` 先 DSH、再 Codex，watcher 不需要知道来源类型。
3. **按 cwd 兜底**：`findLatestCodexRollout({ cwd })` 扫最近两天、按 mtime 降序、匹配 `session_meta.payload.cwd`；`postToolAutoCapture` 在没有 `DSH_SESSION_ID` 时用它自动登记 Codex 会话。
4. **CLI**：`memo session capture --scope ... --codex <file>`；也可 `--codex --session-id <id>` 按 id 找。
5. **UI**：段行显示 `codex` 来源徽标 + 会话尾号（复用 v1.4.2 的 `…sessionId`）。

## 为什么不是别的

- 不做常驻 Codex hook：Codex 没有 DSH 那种进程内事件；MCP 挂车 + watcher 已能覆盖「调工具」和「定时」两个时机。
- 不复制 Codex rollout 到 `~/.memo`：原文件是真相锚，段只存 `source.path`，可回溯、可删除来源。
- 不把 Codex 解析塞进 `captureTask` 的 DSH 分支：source 适配保持单一分派点，测试可注入 fixture。

## 验收

- `readCodexSession` 能把 rollout 转成 `{role,text,ts}`；`findCodexRolloutById` / `findLatestCodexRollout` 命中已知 fixture。
- `captureTask(sourceKind='codex')` 写一段 `source.kind='codex'`，第二次 `created=0`（幂等）。
- `resolveSessionSource` 对绑定 Codex id 返回 `{kind:'codex', file}`。
- 自动捕获：watcher 对 `hostSessionIds` 中的 Codex id 能解析并调用 `maybeAutoCapture`；MCP 工具调用能在无 DSH env 时按 cwd 登记 Codex 会话。
- 真实样例：`01a1ec76-0fc0-7293-8196-d7eba86c6124` 能以 37 turns 写入任务 `20261114-2221-6a5b`，段 `1–38 rules`。
