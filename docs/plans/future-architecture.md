## 0. 结论与定位

Sedimem 是本地优先、可审计、可评测的 Agent 长期记忆与上下文引擎。展示重点是：如何从复杂对话中提取有证据的候选记忆，如何纠错和维护有效状态，如何在 token 预算内提供有用上下文，以及如何用实验证明收益。

- 保留 JSONL append-only 真相层、可重建派生层、治理门禁、MCP、任务账本和观测台。
- 主线改为 **评测 → 证据约束抽取 → 长期记忆接纳与纠错 → 混合检索 → 预算装配 → Agent 任务验证**。
- “不能有错”落实为可执行防线，不承诺开放环境零幻觉：无证据拒绝、未知留空、候选不冒充事实、关键变更人工接纳、严重错误阻断发布。
- 不以 star 数或“功能别人已经做了”否决学习价值；也不以堆框架、图数据库或连接器数量证明 AI-Native。
- 本期不做通用 Agent 框架、聊天产品、云同步、多人权限、自修改系统 Prompt、自动外部动作。

### 0.3 工作规则与红线

1. 文档先行：规格/ADR → 阶段计划 → 失败测试与 eval → 实现 → 文档同步。计划不代替运行契约。
2. TDD + eval；沿用现有 quality/security/coverage/docs-drift 门禁，覆盖率 lines ≥85 / branches ≥70 / functions ≥90。确定性单测与 LLM 效果评测分开报告。
3. 阈值、预算、超时、重试全部进版本配置并记录来源、回滚方法；不得散落魔法数字。本稿评测数字是项目风险取舍，不是论文结论，实施时进入 eval 配置。
4. push/PR 前按既有规定至少两个独立审核（架构、抽取准确性/安全），修完 blocker；本轮文档更新不等于已通过独立审核，不 push、不建 PR。子代理延续用户 GLM-5.3 约束；本环境未提供该模型的独立审核能力；本机 LLM port 当前 provider=none，不擅自启用，不伪称执行。
5. 原始 items 只追加；更新/失效/删除留版本与审计；派生可删可重建。显式维护 compact 的例外及删除含义仍以现行契约为准。
6. trust/taint/sourceRefs 不能因模型摘要、复核、人工“接纳候选”而自动提升；T2 仍不进入可信 facts，trust 提升沿用显式人工操作和理由。
7. 凭据不入 env/仓库/日志；默认不出站。启用模型前明确目的地与发送字段并脱敏；本地存储不等于抽取数据不出机。
8. 语义检索、抽取、来源恢复失败显式 degraded/error；不得把失败当“没有记忆”。同 UID 不承诺机密。
9. 不破坏现有 MEMO_HOME 与记录版本兼容性；新增字段可缺省，变更先 ADR 与迁移/回滚设计。
10. 公共演示使用标明合成的脱敏数据；不得公布真实 transcript、SN、邮箱或本机路径。任务库保持 open，不因本轮研究执行 close/晋升。

## 1. 当前资产与缺口

已有：JSONL、索引、语义 port/RRF、LLM sidecar、checkpoint、segments/brief/expand、trust/taint、注入审计基础、UI。

缺口或需验证：证据到单个 claim 的绑定；跨段角色/否定/纠正；抽取 precision/recall；候选接纳状态机；以 token 为单位装配；端到端任务增益。不能把“已有模块”写成“效果达标”。

最新 handoff 为 P0b 完成、P1 未开始；账本 brief 仍混合 v1.0/v1.2 待办。这作为脱敏回归模式：历史进展可搜索，当前 pending 只能由有依据的最新状态投影产生；矛盾未消解则标 disputed，不能仅取最后一句猜结论。

## 2. 目标数据流与层次

```mermaid
flowchart LR
    A[授权的转录或事件] --> B[规范化与脱敏]
    B --> C[稳定事件及证据片段]
    C --> D[LLM 原子候选抽取]
    D --> E[结构校验及证据核对]
    E --> F[待复核候选]
    F --> G[人工接纳及显式写入]
    G --> H[长期真相层]
    H --> I[混合检索与状态过滤]
    C --> I
    I --> J[token 预算装配]
    J --> K[Agent 任务与评测回执]
```

四类数据分别保存：来源证据（本地授权保留）、候选（非事实）、已接纳长期记录（真相层）、摘要/向量/pack（可弃派生）。session 段继续不进主库 facts；允许 pack 显式检索 ledger，单独 references 分区，不隐式改变主库 search 范围。

复用现有 LlmPort、session 与四道门，不建另一套摄取管道；候选持久化位置、生命周期和 API 在 P1a 规格确定。直接手写 memory_write 保持兼容；新增抽取候选入口不冒充它。

## 3. 上下文抽取：最高优先级

### 3.1 输入与分段

- 保留 role、speaker、tool 状态、task/scope、eventId、事件时间、来源 hash；先脱敏再发模型/落派生盘。
- 按事件/话题及 token 窗口切段，保留必要重叠和回复关系。不能只截前后文而不声明中间缺口。
- 抽取游标只在候选和审计持久化后提交；崩溃重放幂等，缺口有 missingRanges，不能推进为“已完成”。
- 已有摘要只用于导航/辅助指代，不作为新事实的独立证据；来源缺失则拒绝晋升。

### 3.2 原子候选的必要语义（计划字段，非现行 schema）

| 类别 | 必须保留的信息 |
|---|---|
| 身份 | candidateId、schemaVersion、scope/task、输入范围 hash |
| 命题 | 单一 claim、subject/predicate/value、适用范围；未知不猜 |
| 类型 | fact/decision/preference/gotcha/task-state/hypothesis 等语义分类，映射现有 kind 由规格定义，不直接扩 kind |
| 断言 | 谁说的、是否引述、否定/条件、建议/同意/完成/撤销，不能靠关键词拍板 |
| 时间 | observedAt、独立的 assertedValidFrom/assertedValidTo、未来事件时间；相对时间需时区与参考时间，无依据留空 |
| 证据 | source eventId、规范化脱敏版本 hash、原文精确 span、必要邻接上下文；工具结果带结果/退出状态 |
| 关系 | 支撑/纠正/撤回的候选或记忆 ID，必须来自输入允许集合；不能凭空造 ID |
| 血缘 | provider/model 标识、prompt/schema 版本、配置 hash、运行 ID、父来源、trust/taint |
| 工作流 | pending/rejected/accepted，拒绝理由、人工操作者及时间；接受状态与 trust 独立 |

source span 的定位基于版本化、规范化且脱敏后的证据文本；P1a 固定规范化算法、Unicode offset 单位、换行与多字节规则，禁止混用字符/字节位置。证据片段取模型实际见到的带版本快照，而非只保存可变源文件路径。源文件变化时原快照仍可验证；快照不存在/被撤销才标 stale，禁止悄悄把 offset 指向新内容。

`MemoryRecord.validFrom/validTo` 继续表示既有记录版本的系统可见区间，不能填入模型抽到的业务时间。业务时间仅进新的 asserted* 字段及候选 sidecar，未知为 null；v2.0 pack 分开表达 systemAsOf 与 eventTimeFilter。首次写入“去年开始”不能让去年 asOf 查到今天才知道的信息；“下周准备发布”不是已经发布。

### 3.3 六道抽取防线

1. **结构**：严格 schema、枚举、长度、scope 和 ID allowlist；schema 正确不等于事实正确。
2. **证据存在**：span/quote/hash/event 真能定位；证据不完整或已删除，阻止接纳及装配。
3. **语义核对**：检验 claim 是否受证据蕴含、角色是否正确、否定/条件/时间是否保留。可用第二次模型审查提出异议，但它不是可靠裁判。
4. **冲突与纠正**：同 subject/slot 的不同值生成待裁决；“不用 A，改 B”“尚未做”“只讨论过”独立用例。新消息不能因更晚就覆盖已确认事实。
5. **接纳**：v2.0 的抽取候选一律人工逐条/显式批量复核后才写长期库；批量必须展示每条 claim/证据/差异和待执行操作，不能只确认一段摘要。接纳后的普通写入仍是 T2，只进未验证 references；进入可信 facts 还需独立、显式带理由的现有 trust promote 到 T0/T1，并通过状态/证据/taint 检查。界面可展示连续两步，但不可默认勾选或把提升藏进 accept。T3/隔离/注入疑似默认扣留，不进入自动装配。
6. **传播控制**：摘要/归纳继承来源与最低信任，不因派生洗白；纠正/撤回后旧候选、向量、摘要和 pack 缓存失效，查询时再次检查状态。

“用户表示测试通过”只能抽取为用户报告；“工具退出 0”只证明该命令的结果，不证明全项目正确。助手提出计划不等于用户已批准，模型 confidence 不视为校准概率。

### 3.4 失败与 Prompt 管理

- 超时、空响应、解析失败、token 截断、证据不支持、无可记内容分别记录状态；只对已定义的瞬时故障有限重试。空抽取不能掩盖模型故障。
- 失败保留输入游标和可重试引用；规则 fallback 只出带 degraded 的导航/候选，不能降级后悄悄晋升事实。
- 抽取、核对、摘要用独立版本化 Prompt 与 schema；模板中含否定、建议、纠正、条件、无信息的中英反例。
- Prompt 变更在 dev 集调优，test 集只评估；保留模型响应快照（脱敏、受控保留），重放响应后验证确定性后处理。
- 不承诺重新调用 LLM 逐字相同；确定性要求仅适用于冻结输入/候选/时间/配置的校验和装配。

### 3.5 崩溃、并发与事实提交

- 定义 sourceEpoch、rangeId、extractionRunKey、candidateVersion、acceptOpId；同一输入范围/配置重试属于同一逻辑运行，模型差异保留为候选修订而非自动新事实。跨运行的语义近重复仍需复核，不能仅靠文本 hash 声称解决。
- 接纳请求携带 candidateVersion、evidenceHash、expectedTruthRevision；在同一数据锁下刷新校验，来源撤销、候选已变或旧事实版本不匹配则返回冲突，重新展示，不盲写。
- 不承诺多个 JSONL 文件原子事务。人工决定引用与 acceptOpId 必须在事实提交时持久化；长期记录成功追加是提交点。候选 accepted 状态、审计和游标是可按该 opId 补齐的投影；宕机后重复提交返回同一目标记录，不能产生第二条事实。复用既有 noop/merge 时也须保存“opId→目标记录”的持久收据，不能只靠进程内缓存。
- 每范围候选及可恢复审计依据持久化后推进抽取游标；事实未接纳不阻止后续范围扫描，但明确 pending。审计失败显示 audit-pending/error，不能回报完全成功；重启先恢复不完整操作。无法判定 noop/merge 是否完成时标 recovery-required，核对预先持久化的决定/目标版本，禁止自动重试成新写入；P1b 必须通过该故障窗口测试。
- 锁不能覆盖 LLM 网络调用：先固化输入，锁外抽取，锁内核对版本与落盘。测试覆盖两进程同时接纳及每个持久化步骤前后 kill/restart，不用 mock 调用次数替代实际重放结果。

## 4. 长期记忆与纠错

保留 append-only 与当前 supersede/forget；抽取接纳经过现有四道门，不绕过限额、脱敏和 trust。

P1b 就必须支持最小 correction/retraction：人工明确选择旧记录版本、展示新旧证据并调用现有 supersede/forget；语义相似或时间较晚不能自行覆盖。P2 仅扩展细粒度依赖索引与整理效率，不推迟纠错正确性。

P1 保守地按受影响 scope/task 的整体修订使派生过期。缓存输入清单至少包含 truthRevision、ledgerRevision、checkpointRevision、candidate/approvalRevision、evidence/sourceEpoch、deleteRevision、trust/taint/policy、索引及 embedding 版本、Prompt/模型、tokenizer 和 pack 参数。任一改变重新构建；构建前后版本不一致重试或 fail-stale。asOf 固定不等于源集合冻结；hits/访问次数禁止参与 pack 的排序、过滤或缓存内容。

候选接纳后保留其证据和审核引用，证据只证明出处；人工接受不自动赋予 T0。scope 是分类而非权限边界，本期仍是个人部署。

### 4.1 证据、保留与删除范围

- P1a 在数据地图登记新资产：证据快照、候选引文、拒绝样本、模型请求/响应缓存、复核记录、游标/收据、pack、审计及备份。逐项冻结保留期、条数/字节上限、扫描路径和删除验收；未配置禁止真实摄取。
- 证据快照属于授权保留的可删除来源缓存，不是不可删的 items 真相层。到期与显式撤销同样使依赖不可用于普通装配；不得因已提升 trust 而延长保留或重新读取外部原文件。需要更长保留必须先显式变更策略并展示影响。
- 所有新读面（搜索、UI、expand、导出、replay）均按 sourceEpoch 与撤销登记过滤；删除来源必须使新候选无法接纳、禁用在途运行结果、清除上述可删派生正文并禁止自动重新 capture。重新导入须显式授权新 epoch，不能后台复活。
- 逻辑删除不等于物理擦除：items 历史仍可经受控历史查询读取，外部源转录、用户导出和外部备份不在 Sedimem 擦除范围。v2.0 普通 pack 即使 systemAsOf 在删除之前，也不重新注入当前已撤销来源；历史取证接口明确隔离。现行 v1.4 asOf/verify-delete 行为不被本文偷偷改写。
- 验收使用扩展 verify-delete 覆盖新资产与读取面；审计只留最小无正文状态/ID，不持有原文副本。多来源相似内容只根据显式来源边界处理，不能按模糊相似删除无关事实。
- 脱敏后同类占位符不代表同一实体；无法区分的 subject 保持局部来源身份或 unresolved，不得以 `[REDACTED:*]` 相同合并。跨段无明确身份绑定时弃权，记录漏抽原因。

## 5. RAG 与上下文装配

- 首先复用 BM25 / embedding / RRF，比较真实中文改写、标识符、时间更新；检查实际语义道是否 enabled。不得在 semantic-disabled 下报告混合检索效果。
- 检索前后均校验 scope、asOf、status、trust/taint；已撤回/失效信息不能因为相关性高进入 current facts。
- pack 输入：任务查询、scope/task、asOf、includeLedger、目标 tokenizer 和 tokenBudget；目标 tokenizer 不支持时显式报错，或仅出标记 estimated 的预览且不声称硬预算达标。精确模式计算最终序列化 payload（标题、来源、围栏、分区、引用等全部算入），预留宿主指令/工具 schema/回答空间；只保证 Sedimem 分配到的预算，不保证未知宿主的完整窗口。发布效果实验只能用精确模式。
- facts、currentTask、references、unresolved 分区；latest checkpoint 只是待核对的状态来源，不能因“最新”自动成为权威。currentTask 的肯定断言同样受证据、接纳、trust/taint 规则约束，未经确认的自动 checkpoint 仅可作未验证 references；历史矛盾不偷偷选赢家，也不能把 T2 从 facts 搬到 currentTask 绕过规则。
- T2 来源原文默认不注入，包括 ledger 引文；可用结构化且显式标记未验证的 references。显式允许原文仍沿用现行隔离/转义策略，不把围栏当安全保证。
- 结构化字符串同样可能带注入，不作为指令、权限或工具授权；隔离段不进 references，expand 也不绕过。Agent 演示默认只读工具；用本地 stub/canary 检查来源内容不能触发外写/出站，零越权为门槛，不用真实生产外部动作做攻击实验。
- 优先稳定索引与短证据片段，按需 expand 原文。返回 excluded 原因、来源、预算消耗、缺口及降级状态。
- reranker/query rewrite 只在 P3 消融证明必要时启用；模型重写 query 不得改变 scope 或证据边界。
- 每次 pack/inject 留回执：record/version IDs、来源 hash、asOf、配置/模型/Prompt/tokenizer 标识、预算、excluded、packHash；不把正文秘密复制到审计。回执运行时间、runId/latency 放在输出元数据，不能混入要求逐字节相同的 canonicalPack；packHash 只计算 canonicalPack 的规范序列化。
- 区分 preview/generated/exported/delivered/host-ack。无宿主 ACK 只能声称生成或交付，不能声称“Agent 确实看到了”。

## 7. 验收与实验纪律

以下是项目发布门槛，不是已测成绩。数字是准确性优先的初始工程标准，不是论文结论；P1a 在看 holdout 结果前冻结到配置/manifest。任何 test 泄漏、漏样、分母不可追溯均使该轮无效。

### 7.1 数据、标注与评分

| 层 | 冻结要求与发布标准 |
|---|---|
| 语料 | 至少 200 个场景，按来源/场景家族分 dev 100、test 100，近重复不跨集合；test 中中/英文各至少 40 场景，另有混合语言；至少 200 条可抽 gold claim、50 个无可记内容场景（与正场景互斥，允许与对抗标签交叉） |
| 标注 | 每个 gold 包含角色、类型、适用范围、状态、双时间、证据及应拒绝理由；两份互不可见的独立标注后由维护者人工裁决。模型辅助标注可用但需声明模型且不能代替人工；仅同一人重复标注不称独立。未取得复核资源只可做 pilot，不能标为 gold 验收通过 |
| 对抗覆盖 | 否定、建议未接受、后续纠正、条件/假设、工具失败、跨项目同名、跨段指代、时区/相对日期、注入、截断缺口每类 test 至少 10 例；场景可多标签，报告语言/错误类分项 |
| 自动抽取 | 人工编辑/接纳前的“通过机器校验、准备展示复核”的候选：claim precision ≥98%、recall ≥90%，中/英文分别也达标；固定配置至少 3 次运行分别达标。零输出时 precision=未定义且不通过，不能记成 100% |
| 严重错误 | 机器校验后候选/默认装配中，无依据事实、角色错归、否定反转、建议变批准、未做变已做、跨 scope 泄漏、撤回当当前事实，任一出现阻断。原始模型中被正确拦住的错误单独报告，不当成逃逸；零观测不等于总体零错误 |
| 可追溯 | 所有可接纳候选的证据解析率 100%；源已撤销、秘密、缺失证据、非法 ID 必须拦截。精确引用不是语义正确的替代指标 |
| 状态/故障 | 最小纠错、来源撤销、并发 accept、各提交点 crash/replay、游标缺口、不同脱敏实体专项全部通过；相同 acceptOpId 不重复入事实，错误发生前后可恢复 |
| 装配 | 冻结全部修订/参数后 canonicalPack 逐字节复现；最终序列化 payload 不超分配预算；includeLedger=false 不混入段；hits 不改变结果，回执只证明其对应状态 |

原子命题按一对一匹配计分：同一 gold 只计一次 TP，额外重复候选计 FP；范围内 gold 缺失计 FN（包括被过滤/拒绝/unsupported 而漏掉的）。语义正确但 gold 漏标先裁决并版本化 gold，再重跑全部组，不能临时给自己加 TP。事实正确但格式/冗余不合约与严重事实错误分别标注。

同时报告三层：原始模型输出（错误率/无效结构）、机器校验后候选（发布精度/召回）、人工处理后长期记录（人工纠错收益与工时）。拦截率、每场景复核数量/耗时、无可记场景误报率不得省略。token 截断/超时/解析失败均在原分母保留并计缺失，不作为空场景排除。

测试场景内 claim 相关，三次模型运行也不是三倍独立样本。保留 TP/FP/FN、各场景计数及每次运行结果，置信区间以场景家族聚类 bootstrap 为主；可附 Wilson 描述区间但不能据此宣称独立样本置信保证。方法、随机种子和轮数写入冻结配置；区间过宽如实报告。

### 7.2 防泄漏、预算与端到端任务

- 抽取只能看到该次 queryTime 之前、已授权的历史及相应系统可见记忆；禁止把 test gold、标准答案、queryTime 之后的事件/纠正、人工后处理内容、评测员说明放进抽取/检索。queryTime 之前的合法纠正应正常参与。评分器与被测 Agent 使用隔离目录/权限/输入清单；query 仅在真实任务提问时可见，不能提前影响历史记忆摄取。
- 在同一冻结语料和可见时间点比较无记忆、最近窗口、BM25、混合检索、混合检索+pack。后两组必须共享同一可用记忆、人工接纳与 trust 提升结果；仅 pack 组获得人工选证据的实验无效。分别报告 oracle（金标准记录）和端到端（实际自动候选+显式人工接纳）轨道，不能混用成绩。
- 端到端至少 30 个独立 holdout 跨会话任务（另备 dev 任务，不从这 30 个里调参），固定回答模型、解码参数、工具权限、上下文上限和回答额度；每任务每组至少 3 次运行，成对比较任务平均成绩。人工 gold 接纳/编辑/提升工时计入摄取成本，不能伪称全自动。
- 同预算表示相同上限而不是强行填满；计算最终 memory payload token（含元数据/围栏）并报告总输入和上游抽取/核对成本。发布收益：相对混合检索，pack 必要证据覆盖率不下降、memory token 中位数至少降 20%、任务成功率不下降；三项均满足才称收益成立。空基线或全无证据的退化任务单独报告，不能制造百分比收益。
- 固定最低实验配置和总成本后再运行；按任务聚类给出配对差值与区间，不把 3 次采样当 90 个独立任务，不以点估计未下降宣称统计非劣效。任务完成/证据判定规则在实验前冻结；模型评分只作辅助，分歧/严重错误人工裁决。
- test 首次暴露后的样例进入 regression，不能再称未见 holdout。失败后保留原失败报告，模型/Prompt/阈值调整只看 dev；下一次泛化放行须补未暴露的同协议 holdout，不在同一个测试集反复改到过关。公共 LongMemEval 使用 cleaned 版本并标子集规模，不能把已公开数据称保密 holdout 或把子集成绩写成完整榜单。
- 范围收窄须先发布新能力/评测版本并保留旧集完整结果，不删难例。pilot、工程回归通过、holdout 放行与产品发布是四种状态；未配置费用、未完成独立标注、无精确 tokenizer 或真实语义道不可用时，只报告对应试跑，不伪造完整验收。

## 8. 可行性、取舍与停止条件

- 可行：现有存储、MCP 和模型 port 已够用；新工作集中在证据候选和评测，无需另起平台。
- 主要成本：标注/复核、中文指代和时间、候选生命周期、缓存失效。不能以“有 JSON 输出”估算抽取已完成。
- P1b precision 未达标：缩小支持的内容/语言/来源范围，明确 unsupported，继续调 dev；不默认放宽精度或开启自动晋升。recall 不达标不能靠全拒绝发布。
- pack 无收益：保留原 brief，发布实验与负面结果，停止为 UI/新模块继续扩张，不强行宣传节省。
- 只允许一条主线、一个首发来源；独立审核者不能由主代理自行冒名。任何真实模型试验前确认成本配置，不用真实私密历史作公共样本。
- zero-runtime-dependency 内核继续保留；未来确需 tokenizer/其他库先 ADR 评估依赖范围，不能为零依赖牺牲正确性，也不在本文偷偷引依赖。

### 8.1 单人可维护性与成本闸门

- P1b 首发先提供一个完整 CLI 复核流程（list/show/diff/accept/reject/status），复核 UI 后续复用同一 API，不强制两套界面同时首发。人工接纳耗时、每场景点击/复核次数单独报告，不能把人工成本藏在“自动记忆”宣传里。
- 新增 extract/verify 的用途与输入输出上限必须进入 LlmPort policy；当前 derive/checkpoint 的字数粗估与输出额度不适合作为新抽取的正确性保障。增量 chunk 需覆盖格式/JSON/证据引用开销，finish_reason 截断必须识别，不解析半截响应。
- 在真实模型调用前配置每次/每天总成本、并发、重试、最大输入输出、每来源候选/证据配额。瞬时失败重试按实际调用计费，成本预占/结算跨进程幂等，超过任何上限显式停机而非丢弃未处理范围。先小批试跑验证用量，再进行冻结实验。
- tokenizer 可用外部可选适配，内核仍零运行时依赖；P1a ADR 必须选定一个有精确 tokenizer 的目标模型组合及许可/分发方式，无精确实现不能开正式效果实验。embedding 索引固定模型/维度/数据版本，重建未就绪不作为混合检索组。
