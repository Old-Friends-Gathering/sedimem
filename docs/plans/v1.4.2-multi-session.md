# v1.4.2 任务库多会话关联

状态：已完成（PR #261 已合并）

## 问题

任务库 `meta.json` 只有单值 `hostSessionId`。一个任务由多个 DSH 会话接力开发时，只有最近一次 `bind` 的会话会被自动捕获；其他会话的段靠手工补捕，且 `bindSession()` 覆盖旧值，换会话即丢关联。

## 改动

1. `meta.hostSessionIds: string[]` 保存全部已关联会话；`hostSessionId` 保留为最近一次 bind 的主会话。
2. `readBoundSessionIds(memoHome, taskId)`：兼容只有 `hostSessionId` 的旧 meta，去重、主会话在前。
3. `rememberSession()`：agent 在任务库调用 `memory_session_*` / `memory_write(scope)` 时自动追加当前会话；已存在零写入。
4. watcher 按 `hostSessionIds` 逐个捕获；`autocapture.json` 增加按会话的 `sessions[sid]` 状态，旧顶层状态继续兼容。
5. `listOpenTaskIds` 同时识别登记文件与 `sessions/<taskId>/meta.json`，避免丢登记文件后任务不再被扫描。
6. UI 沿用「N 个转录」徽标；默认全部，可切单会话。

## 验收

- 同一任务依次 bind A、B，`hostSessionIds=[A,B]`，两个会话都有段。
- agent 用任务库后无需手工 bind，当前会话自动出现在 `hostSessionIds`。
- watcher 对 A/B 各调用一次，状态按会话隔离。
- 旧 meta（只有 `hostSessionId`）读取不报错。
- `HOME=/tmp/emptyhome npm test` 全绿；quality/docs-drift/security 通过。
