# 金融工程 / 运筹学 / 控制论方法在 sedimem 记忆系统上的应用（2026-11）

> 范围：方向（1）记忆更短更原子、方向（2）开发期临时记忆库压缩策略。方向（3）纯前端，无数学，不在本文。
> 数据源：`~/.memo/events.jsonl`（op=write|hit|supersede|forget|search…）、`~/.memo/metrics/<date>.<scope>.json`（30+ 天）、`~/.memo/items/<scope>.jsonl`（hits 计数）。
> 每条方法标注：【现有数据可标定】/【需新埋点】。

---

## 1. Newsvendor / 报童模型 → brief 行数与 active 配额

- **人话**：报童每天决定进货量——进多了砸手里（超储），进少了错过顾客（缺货）。对应：brief/保留的记忆条数 Q。
- **公式**：最优分位数 `F*(Q) = Cu / (Cu + Co)`，即需求的 Cu/(Cu+Co) 分位点。
  - 缺货成本 Cu = 一条「本该在 brief 里却没有」的记忆导致多花一次 search / 任务失败的代价；
  - 超储成本 Co = 一条多余记忆占用的 token + 稀释注意力的代价。
- **优化旋钮**：`brief.lines`、`brief.tier0Chars`、`brief.totalChars`、`quota.maxActive`。
- **用现有数据估 Cu/Co（【现有数据可标定】）**：
  - Cu 代理：metrics 里 `noHitRate`（搜了没命中）与 `staleHitRate`（命中过期版本）→ 每次未命中约等于一次往返（可按一次 LLM 调用延迟+费用折算成同一货币单位）；events.jsonl 里 op=search 的 `hits=0` 次数 × 平均重试成本。
  - Co 代理：brief 每行字符数 × token 单价 + 用 A/B 对照（brief.lines=60 vs 80）时任务完成率差异来反推注意力稀释项。
  - 需求分布：以「单次任务实际引用的记忆条数」为需求 X，从 events.jsonl 的 hit 序列按任务聚合（可用 qHash 聚类近似同一任务），取经验分位数。
- **机械验收**：改 lines 后 7 天窗口 `noHitRate` 不升、brief token 开销下降 ≥15%。
- **失败模式**：Cu/Co 货币单位不一致导致比值瞎算；hit 事件无法归因到任务（需 qHash 或会话 id 兜底）；需求分布非平稳（换项目后失效）。

## 2. 最优停止 / 动态规划 → 压缩触发阈值

- **人话**：固定 30k 压缩像「固定每 10 分钟喝水」；最优停止是「渴了才喝，且预计马上有水源就再忍忍」。
- **固定阈值为何在长尾任务系统性偏晚**：压缩决策只有「当前占用」一个状态，不含「剩余任务时长/信息仍会被用到」的期望；长尾任务里旧上下文的边际价值持续为正，30k 一刀切时要么压太早丢信息（短任务）、要么太晚白背 token（长任务）。可回放反例设计：取一个历史长会话（events.jsonl 中 compact op 前后），把 compact 前窗口内容按「后续是否再次被引用（后续 hit/search 词重叠）」打分，统计固定阈值下被误压的比例——这个 replay 脚本【现有数据可标定】（若 compact 未记录窗口快照则降级为【需新埋点】：compact 时 dump 压缩对象清单）。
- **阈值函数形式**（DP 的简化一阶近似）：
  `压缩当且仅当 U(t) ≥ U* = f(剩余不确定度)`；具体：`U* = base + β·H_recent − γ·G`，
  - U(t)=当前占用率，base=硬上限（如 85%）；
  - H_recent=近期新颖信息速率（新工具输出 token/轮，高→早压）；
  - G=边际信息增益 = 下一轮引用旧窗口的预测概率（可用「过去 k 轮中旧窗口被引用的频率」估计，简单在线平均即可）。
  这是带终局约束的贝尔曼方程的线性代理：真实 DP 需知道任务长度分布，用代理绕开。
- **机械验收**：replay 上动态阈值的信息损失率（误压率）< 固定 30k，同时平均占用率不升。
- **失败模式**：G 估计滞后（等发现要用时已压掉）；振荡（见 §7 滞回）；特征工程过度拟合当前项目。

## 3. 生存分析 → decay.halfLifeMs 标定

- **人话**：统计「一条记忆出生后多久没人再想起」，像统计病人存活时间，拟合出衰退曲线替代拍脑袋半衰期。
- **方法（【现有数据可标定】）**：
  - 事件时间：items 里每条的 `createdAt` → 最后一次 hit 时间（hits>0 时）；hits=0 的按 createdAt 至今。
  - **删失（censoring）**：至今仍活跃（最近 7 天有 hit）或被 supersede/forget 的记录不是「自然死亡」，是删失观测——KM 曲线必须把它们当右删失，否则半衰期被系统性低估。
  - 用 Kaplan–Meier 出无检索生存曲线 S(t)；若想外推尾部，拟合 Weibull `S(t)=exp(−(t/λ)^k)`：k>1 说明记忆有「婴儿期」 protection（早期不被检索的大概率永远不被检索），k<1 说明长尾黏性。半衰期 = λ·(ln2)^(1/k)。
  - 按 kind 分层拟合（fact/pref/decision/gotcha 半衰期应不同），分别写进 `decay.halfLifeMs`（当前是全局单值 → 建议改成 kinds.*.halfLifeMs，新旋钮）。
- **机械验收**：拟合的 S(t) 与 KM 非参曲线在 t∈[1d,90d] 的最大偏差 <10%；替换半衰期后 30 天 `staleHitRate` 不升、active 数量下降。
- **失败模式**：hits 只记次数不记时间戳 → 最后 hit 时间不可得（检查 items 结构；若无 per-hit 时间，用 events.jsonl 的 hit op 时间戳回填，仍缺则【需新埋点】：hit 事件必须带 ts——events.jsonl 本身有 ts，此项大概率已有）。

## 4. Kelly 准则 —— 部分适用，只取其直觉

诚实结论：**完整 Kelly 不适用**，因为这里没有可复利的重复赌局——「保留一条记忆」不是按赔率结算的独立下注，收益（未来某次检索省下的成本）是稀疏、不可观测结算、且各注高度相关的。强行套 f* = edge/odds 会伪造精度。
真实价值是一个临界直觉：**Kelly 上限告诉我们不要满仓**——对应「不要把上下文 100% 塞满信息（过保留），也不要过度压缩到只剩摘要骨架（过压缩，f 过小）」；分数 Kelly（half-Kelly）对应工程实践「留 20–30% 自由上下文做缓冲」。这值得写进文档一句话，不值得写代码。**对等常识**：留 buffer，别把窗口塞满。

## 5. Markowitz / Thompson sampling → 检索混合与在线调参

- **Markowitz（组合权重）**：RRF 融合 BM25 与语义道，当前 k=60 固定。人话：不要单押一匹马，按「期望收益−λ·方差」配组合。
  - 目标 `max wᵀμ − λ wᵀΣw`，w=两道权重，μ=各道期望相关性（用 search 事件后续是否被 hit 的比率当 label），Σ=两道得分协方差。risk-averse 检索 = 高 λ：在两道分歧大的 query 上倾向融合而非单道。
  - 【需新埋点】才有可靠 μ：search 时记录「返回候选来自哪条道 + 哪条最终被 hit」，即 per-道 attribution。现有 qHash 只能做粗对照。
  - 机械验收：离线 replay 一批历史 query，加权 RRF 的 MRR@5 ≥ 固定 k。
- **Thompson sampling（多臂老虎机）在线调 k / dedupe 阈值**：人话：每个参数值是一台老虎机，奖励=检索质量，边玩边学，不确定时多探索。
  - 把 k∈{20,40,60,80,120} 当臂，奖励 r = 1/(1+rank_of_first_hit)（events.jsonl 的 search hits 可回放；线上需【需新埋点】记录每次 search 的 k 值与命中排名）。
  - Beta–Bernoulli（命中与否）或 Normal-Gaussian（MRR）后验，每次 search 后更新；每周取后验均值最优臂。
  - dedupe 阈值同理：奖励 = 人工 curate 决策与自动聚簇的一致率（curate_apply 事件已有，【现有数据可标定】做离线回放，在线版本需埋点）。
- **失败模式**：非平稳（换 embedder 后奖励分布全变，需重置后验）；探索期线上质量抖动（限定 ε 或 TS 收缩）。

## 6. VaR / CVaR → 单会话上下文爆掉的风险预算

- **人话**：VaR 回答「95% 的坏情况下最多亏多少」；这里是「95% 的会话最多用掉多少上下文」。
- **预算形式**：`P(token_usage ≤ 0.70 × window) ≥ 0.95`，即 VaR₉₅(token) ≤ 70% 窗口。CVaR（条件在险值，尾部均值）更严：最坏 5% 会话的平均占用 ≤ 85%。
- **估法**：历史 token 用量分布的分位数。**数据缺口**：现有 metrics 无 per-会话 token 序列 → 【需新埋点】（compact op 的 detail 里补 pre/post token 数即可，改动极小）。替代方案：在嵌入/compress 事件里用字符数 × 0.6 估 token，先出粗 VaR 验证流程。
- **机械验收**：压缩策略上线后滚动 30 天 VaR₉₅ ≤ 目标线。
- **失败模式**：分布厚尾（一次超大文件读入毁掉一切）——正是要用 CVaR 而非 VaR 的原因；样本量不足时分位数估计噪声大（用 CVaR + 参数化拟合更稳）。

## 7. 控制论 → 滞回双阈值压缩控制器

- **人话**：占用率是水位，压缩是放水闸；PID=按水位偏差比例/积分/微分地开闸；滞回=水位降到 55% 才关闸，涨到 75% 才开闸，防止在 65% 附近反复开关。
- **结构**：被控量 y=上下文占用率；执行器=compress；建议 **PI + 滞回** 而非完整 PID（D 项对突发大输入过敏，会产生过激压缩）：
  - 上阈值 y_h=75% 触发压缩，压缩目标 y_target=55%（滞回带 20 个百分点）；
  - 积分项仅用于慢漂移（长期平均占用），加 anti-windup（压缩不可用时暂停积分）。
- **为什么滞回防抖动**：单阈值下，压缩后回落、随后 1–2 轮又涨回阈值附近，触发器在开/关间振荡，每次半压缩都是信息损失 + 成本；滞回带宽度 ≥ 单轮平均增量 × 3 才有效（用 events.jsonl 相邻 compact 间隔的 token 增速标定，【现有数据可标定】，若 compact detail 无 token 数则退化为字符代理）。
- **参数整定**：Ziegler–Nichols 太重；直接用数据——上阈值 = 历史占用分布 p85，目标 = p50，滞回带 = p85−p50。
- **机械验收**：每千轮压缩次数下降 ≥30%，无「连续 5 轮内二次压缩」事件。
- **失败模式**：突发超大注入一步越过阈值 → 滞回无关，需要「超硬上限强制压缩」旁路；P/I 参数跨模型窗口大小不可迁移（按窗口比例而非绝对 token 表述）。

## 8. 诚实评估

**换个名字讲常识**：
- Kelly：留 buffer，别塞满（§4）。
- VaR：给尾部留余量（§6 的本质）。
- 固定阈值偏晚：压早丢信息、压晚费 token——不用 DP 也知道；DP 的增量只在给出「多早/多晚多少」的量化。
- 滞回：开关别贴着阈值，常识；量化贡献是滞回带宽度公式。

**真的带来可测收益**：
- 生存分析标定 halfLifeMs：完全数据驱动替代拍脑袋，且 kind 分层是纯增量——最高置信度。
- 滞回双阈值 + 按分位数整定：机械验收简单，防振荡收益可测。
- Newsvendor 定 brief.lines：若能打通「hit 归因到任务」，是从猜到算的实质变化。

## 推荐实施 3 条

1. **生存分析标定 decay 半衰期（按 kind 分层，Weibull + KM，右删失处理）**——数据全在 items + events.jsonl，产出直接写 policy 新旋钮 `kinds.*.halfLifeMs`。
2. **滞回双阈值压缩控制器（上=p85、目标=p50、滞回带≥3×单轮增量，PI 带 anti-windup + 硬上限旁路）**——替代固定 30k，整定数据可从 compact 事件回放。
3. **compact/search 事件补 token 数与 per-道 attribution 埋点**——一次性小改动，解锁 Newsvendor（brief 行数）、VaR（爆窗预算）、Thompson sampling（RRF k）三条线的后续标定。

## 明确不做

- Kelly 准则任何代码化——只留一句「half-Kelly = 保留 20–30% 自由上下文」的设计直觉。
- 完整动态规划求解压缩策略——状态空间不可枚举，用 §2 一阶代理即可。
- 在线 Thompson sampling 先不上线——先离线回放（dedupe 阈值臂可用 curate_apply 数据验证）。

## 未验证清单

- hit 事件是否可靠携带每条记忆的最后命中时间戳（决定 §3 走 KM 还是需埋点）。
- qHash 聚类能否把 search 归因到任务（决定 §1 需求分布可行性）。
- compact 事件 detail 是否含 pre/post token 数（决定 §6/§7 是字符代理还是真值）。
- Weibull k 是否 >1（「婴儿期保护」假设）——拟合前纯属猜想。
- 加权 RRF 相对固定 k=60 的 MRR 增益——无 per-道 attribution 前无法测。
