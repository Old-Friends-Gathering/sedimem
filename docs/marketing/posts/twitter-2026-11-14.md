**1/6**

Your AI forgets you every session.

I got tired of re-teaching Codex / Claude Code / DSH the same project facts, so I built **sedimem** — a local-first memory layer they all share.

This week's release: **LLM-written titles** and a **session scratchpad**.

🧵

---

**2/6**

Why not just CLAUDE.md / AGENTS.md?

Those are instructions. Memory needs an append-only truth layer (JSONL, never edited in place), as-of queries, and everything else rebuildable.

Zero runtime deps. Data stays in `~/.memo/`.

---

**3/6**

New this week:

🧾 LLM titles — human sentences, not `subject/predicate` soup
🗂 9-page read-only UI: today / 3D graph / search / hygiene / session
🧹 LLM checkup on my own 33 memories: 5 test leftovers + 2 dupes found → 30, dup rate 0
🔌 1 MCP server, 3 clients

---

**4/6**

Not everything should become long-term memory.

So there's a session layer: `start` → `checkpoint` (8 fixed fields: intent, files, errors+fixes, next steps…) → `close`.

On close only decision / gotcha get promoted into the main store, tagged. Rest dropped + a handoff doc.

---

**5/6**

Why the session layer matters: mid-task state ("I'm on step 3, the lock file is the blocker") is useless next week but essential tomorrow.

Long-term store stays clean; the scratchpad is disposable. Same MCP server, so Codex and Claude Code see it too.

Handoff > re-explaining.

Run it for a week with your agent, then tell me what's confusing or wrong. I fix issues same day.
