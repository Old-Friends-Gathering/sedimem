## 正文

你是不是也这样——

换个会话，AI 就把你忘了 😅 上周聊定的技术方案，这周它一脸茫然。于是你开始往 AGENTS.md 里塞规则，塞着塞着发现：文件越写越长，新旧条目互相打架，AI 反而更糊涂了。

问题的根子：AI 缺的不是上下文，是一份**不会烂掉的记忆**。

我做了 sedimem，本地优先的个人 AI 记忆系统，开源在 GitHub（Old-Friends-Gathering/sedimem）。

它怎么解？三个设计 👇

📖 **真相层 append-only**：每条记忆只追加不覆盖，JSONL 落盘，任何一条都能 as-of 回查到"当时它说的是什么"。索引坏了可重建，派生物永远不是真相。

⚖️ **Agent 当裁判去重**：记忆攒多了必然重复冲突。sedimem 用 containment + Dice 发现候选，让正在干活的 Agent 顺手裁决，零额外 API 成本。失效不删除，bi-temporal + tombstone 留全痕迹。

🔌 **三端共用一个 MCP server**：DSH / Codex CLI / Claude Code，10 个 memory_* 工具，一份记忆三处生效。

优势清单 ✅
- 零运行时依赖，Node ≥22，SQLite 用内置 node:sqlite
- 写入门控零误杀，检索带 basis，语义道不可用时显式降级
- 本地 7788 观察台：3D 记忆图谱 / 冗余率·冲突率 / 检索健康
- launchd 常驻，nightly 03:30 自动整合
- 不上云、不自动写入，半自动捕获需人工 accept

3 步部署 🚀

```bash
git clone https://github.com/Old-Friends-Gathering/sedimem
bash sedimem/scripts/install-dsh-plugin.sh   # 一条命令装 DSH 插件
# 三端 MCP 各自贴一段配置（docs/06-usage.md 里有现成的）
# DSH 里跑一句：memory_scope use path=<你的项目根>  ← 让三端指向同一份记忆
```

自测数字 📊
- 391 tests 全绿；36 个注入式评测
- 质量门禁 9 项 + 安全门禁 9 项；覆盖率 93%/92%；brief ≤80 行

一条诚实的边界 🧱
不做云同步、不做团队共享、也不替你自动记东西——半自动捕获必须手动 accept。想要"无感全自动"的同学可能要失望，这是有意为之。
